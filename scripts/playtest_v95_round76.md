## 🔧 本轮修复

### #383 副本战斗血量同步 DB（commit 8923769 + ea94762，紧急）
**根因链**（格温副本实测）：副本战斗中玩家 hp/mp 只存 `st["players"]` 快照，**从不写回 DB**（DB 保持开本时的值 1003/1003）：
1. 层肃清后（boss=None 战斗外）『使用 治疗药水』→ 治疗判定读 DB 满血 1003/1003 → **"你现在的生命是满的"拒用**（实际快照残血 197）
2. 紧接着进 Boss 战第一回合 → 快照残血 **197/1003 开局**（丢 800+ 血）
3. 战斗中喝药正常（战斗内读快照）→ 但战斗外无法囤积血量，Boss 战只能以残血开局 → **#349 无法通关的直接原因**
- **修复**：新增 `_sync_players_db()`（instance.py）——三个写回点：每回合行动保存前 / 切下一只怪前 / 层肃清后，把快照 hp/mp/max 同步 DB
- **#383b 补充**：层肃清后战斗外行为（喝药/调查回血点）只更新 DB 不更新快照 → 『深入』后以旧快照残血开战药白喝（实测 364→564 快照仍 364）。`_enter_stage_combat` 开头用 DB 刷新快照
- **验证**：新测试 `tests/test_v95_76_instance_hp_sync.py` 5/5 ✅；回归 test_commands_instance 71 ✅ + test_instance_map 61 ✅ + test_v95_75_item_use_fix 8/8 ✅；重启后 loopback 实测：层肃清后 DB 364==快照 364 同步、『使用 治疗药水(小)』恢复 200 → 564 正常（修复前误报满血拒绝）、Boss 战开局快照 564==DB 药不白喝 ✅

### #381b 洗点后 HP 倒挂（commit f37283b）
**根因**：洗点把 attributes 清零 → max_hp 下降（956→796），当前 hp 不裁剪 → 面板"❤️ 生命：956/796"倒挂（小白实测）。#381 的 MP 分支没倒挂只是碰巧当前值未超。
- **修复**：reset_attr 洗点后用 `E.player_final_stats` 实时计算新上限，hp/mp 裁剪到上限内
- **验证**：test_store_players 12 ✅ + test_commands_skills 41 ✅；重启后 loopback 实测：小白洗点 → "❤️ 生命：796/796(+438)" 不再倒挂 ✅（加点回耐力后 796/956 属正常设计）
