## 🛠️ 本轮修复（3 项，全实测验证）

### 🔴 #268 组队 UNIQUE 冲突（#47b 第 7 轮卡死根因，弃游级）
- **现象**：小蓝『组队 小芽/小红』→ `❌ 快捷指令执行出错：UNIQUE constraint failed: party.group_id, party.member`（3 次稳定复现）；副本无法开本
- **根因（代码实锤）**：party_create（store/social.py）里 INSERT 新成员行**先于** DELETE 该成员旧队伍行——目标成员（小芽）还在旧队（小红队）时 INSERT 直接撞主键。party_add 顺序正确（先删后插），party_create 写反了
- **修复**：对齐 party_add 模式——先 `DELETE member 旧行` + `DELETE member 当队长的行` 再 INSERT
- **实测**：『组队 小芽』→「🤝 组队成功！你和 小芽 成为队友」✅
- **测试**：test_commands_instance 71 通过 + test_commands_social 13 通过，全绿

### 🔴 #269 副本战斗『使用』药水覆盖副本上下文（#47b 第 8 轮卡死根因，弃游级软锁）
- **现象**：小蓝副本中『使用 治疗药水』→ 恢复 0 点生命（满血正常）+ 普通战斗界面 → 随后『攻击』报 `'members' KeyError`、『深入』报"没有分层结构"、『副本地图』报 `'inst_id' KeyError`、『探索』报"正在战斗中"——**玩家被锁死在损坏副本状态**（无法逃跑/撤退/攻击）
- **根因（代码实锤）**：economy.py `use` handler 战斗分支只分流了 pvp，**漏掉 instance**——副本战斗中『使用』走普通战斗分支：`BT.Battle.from_state(instance上下文)` → `db.save_battle(qq_id, b.to_state())` 把 leader 名下保存的 **instance 上下文覆盖成战斗引擎状态**（丢 members/inst_id/players/leader）。对比 combat.py 攻击/技能/防御三处都有 instance 分流
- **修复**：use handler 加 instance 分流 → 道具效果结算后路由 `_instance_act(action="use_item", payload)`（走副本轮流回合 + 正确保存上下文）
- **实测**：副本中『使用 治疗药水』→「💊 恢复 204 点生命！(495/516)」+ 副本战斗界面（Boss 血量/轮到小芽）✅，后续『攻击』正常 ✅
- **测试**：test_commands_instance 71 通过，py_compile 全绿

### 🟡 #270 party_members 返回顺序错乱（队长标记/拉人权限误判）
- **现象**：小蓝（真队长）『组队 小红』被拦「你已在队伍中，让队长『组队 <名字>』拉人吧」；『队伍』显示「1. 小红(队长) 2. 小蓝」——**真队长被误判成队员**
- **根因**：party_members 的 `SELECT member WHERE leader=?` **无 ORDER BY**——SQLite 返回顺序不保证，members[0] 被命令层当作队长（显示标记 line 313 + 拉人权限 line 334），顺序错乱即误判
- **修复**：`ORDER BY (member=leader) DESC, rowid` 队长自指行恒排第一
- **实测**：『组队 小红』→「1. 小蓝(队长) 2. 小红」✅
- **测试**：test_commands_instance 71 + test_commands_social 13 全绿
