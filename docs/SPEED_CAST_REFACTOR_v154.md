# v154 战斗引擎重构：速度 = 出招/收招（读条命中制）

> 鱼鱼拍板（2026-09-01，v153 职业重做完成后）：
> **速度只影响自己的出招速度和收招速度；出招跑完了就是命中了对手。**
> 需要做引擎调整 + 职业数值重平衡。

## 〇、为什么改

v152 模型（当前）：总行动周期 = 恢复间隔（速度定）+ 固定动作耗时（数据定）
- 速度只影响"多久能再行动"（BASE_DELAY/spd 恢复等待），动作本身耗时固定
- 玩家行动**立即结算伤害**，读条（cast）只是"装饰性"影响下次行动时间
- 问题：速度收益被"恢复间隔"主导，动作快慢只是点缀；伤害立即结算导致"读条"没有真实感

v154 新模型（鱼鱼拍板）：**速度影响出招(cast)和收招(recovery)，出招跑完 = 命中**
- 伤害从"立即结算"改成"**出招读条结束才结算**"（真·出手时序）
- 敌我对称：敌方也有出招读条，出招结束才命中玩家
- 控制类（眩晕/冻结/沉默）**打断读条**（惩罚重：行动白费、资源不返还）
- 总周期 = 出招 + 收招，**恢复间隔取消**——速度收益全部收敛到动作快慢

## 一、核心模型

### 1.1 速度折算公式

```
动作总耗时 = 出招耗时 + 收招耗时
出招耗时 = 基础出招 × (基准速度 / 实际速度)
收招耗时 = 基础收招 × (基准速度 / 实际速度)
```

- **基准速度（SPD_REF）= 50**（= v152 参考档，速度 50 时耗时 = 基础值）
- **实际速度**：`min(spd, SPD_CT_CAP)`（沿用 80 软上限，防极端速度爆炸）
- 速度 >50 → 出招/收招变快；速度 <50 → 变慢
- 职业特色保留：重剑普攻基础 1.4s 即使快人也比匕首 0.7s 慢（基础值差异保留）
- 恢复间隔取消：不再有独立的 `BASE_DELAY/spd` 等待段

### 1.2 读条命中制

- 玩家行动（普攻/技能/道具/防御/逃跑）→ 排 `cast_done` 事件（t = now + 出招耗时）
- **出招跑完 = 命中**：`cast_done` 触发时结算伤害/效果
- 收招耗时在命中后追加（`next_act_at = 命中时刻 + 收招耗时`）
- 读条期间（出招未完成）：
  - 敌方可行动（真时刻制，v152 已有）
  - 玩家被控制（眩晕/冻结/沉默）→ **打断读条**：行动白费、资源不返还、伤害不结算

### 1.3 事件队列

- 复用 v152 事件队列（`self._events` heap）
- `cast_done` 事件激活：payload 携带 `{"kind": "player_skill"|"player_atk"|"player_item"|"enemy_act"|..., "skill": ..., "target": ...}`
- 事件触发时：
  - 玩家侧：执行伤害/效果结算（原 `_do_player_skill`/`_player_attack` 的结算部分）
  - 敌方侧：执行敌方伤害结算（原 `_enemy_turn` 的伤害部分）
- 结算完成后：`next_act_at = 命中时刻 + 收招耗时`，排下一次行动

### 1.4 打断规则

- 打断条件：读条中受到 眩晕/冻结/沉默（控制类）
- 打断效果：读条清空、行动白费、**资源不返还**（MP/核心资源照扣）
- 控制施加方：玩家控制技能 / 怪物控制技能（MON_CTRL_EFFECTS）
- 防御（defend）不打断（防御是即时动作，无读条）
- 逃跑读条被打断 → 逃跑失败

## 二、改动点清单

### 引擎层（game/battle.py，主 agent 亲写）
1. `BASE_DELAY` 语义废弃 → 改为 `SPD_REF = 50.0` 基准速度
2. `_ct_cost(spd)` → 废弃或改为"出招/收招折算系数" `_spd_mult(spd) = SPD_REF / max(1, min(spd, SPD_CT_CAP))`
3. `_action_cast(kind, player, skill, item)` → 拆成 `_action_cast_time`（出招）+ `_action_recovery_time`（收招），都乘 `_spd_mult`
4. `_after_actor_ct` → 改为只排"下一次行动"（= now + 收招耗时），不再包含恢复间隔
5. `player_turn` → 玩家行动不立即结算伤害，改为排 `cast_done` 事件（t = now + 出招耗时）
6. `_process_until` → 激活 `cast_done` 事件分支：玩家侧结算伤害/效果、敌方侧结算
7. `_enemy_turn` → 敌方行动也排 `cast_done`（出招结束才命中玩家），不再立即结算
8. 打断：`_process_until` 处理敌方行动时检查玩家是否在读条中且被控制 → 打断
9. `to_state`/`from_state` → 序列化读条中状态（cast_pending）

### 数值层（game/data/）
1. `battle_config.py`：新增 SPD_REF；CAST_* 语义从"固定耗时"改为"基准耗时"
2. `classes.py`：cast_atk/cast_defend/cast_flee 改为基准耗时（7 职业）
3. `skills_v153.py`：技能 cast 改为基准耗时（294 技能）
4. `skills_v151_overrides.py`：技能 cast 覆盖同步（火球术 1.8s 等）

### 敌方对称
- `monsters.py`：MONSTER_SKILLS 加 cast（或引擎默认）
- `_enemy_turn`：敌方普攻/技能排 cast_done 事件

## 三、铁律（不可破坏的语义）

1. **伤害公式、暴击/闪避/格挡/穿透/韧性、装备词条、被动、符文、药水效果数值、宠物、召唤、AOE、站位/射程/仇恨/嘲讽、Boss 机制数值** —— 全部不动，只改"触发节奏"
2. **PVP（btype=="pvp"）不介入**——保持真人轮流异步（CTB 调度不参与）
3. 玩家一次操作 = 推进到下一次玩家可行动点（交互节奏不变，QQ 聊天体验优先）
4. 存档兼容：旧档 from_state 兜底照旧
5. 控制类打断读条 → 行动白费、资源不返还（鱼鱼拍板）
6. 出招跑完 = 命中（鱼鱼拍板核心语义）
7. 敌我对称（鱼鱼拍板：敌方也有出招读条）

## 四、数值重平衡

- 速度 50 = 基准（耗时 = 基础值）
- 速度 25 → 耗时 ×2（慢一倍）
- 速度 75 → 耗时 ×0.67（快 33%）
- 速度 80（cap）→ 耗时 ×0.625（最快）
- 战斗时长参考：v152 普通怪战 ~49s；新模型需模拟标定（scripts/sim_ctb_v152.py 改）
