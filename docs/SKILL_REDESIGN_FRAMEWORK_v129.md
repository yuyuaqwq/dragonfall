# v129 技能系统主设计框架 —— 唯一定稿基准

> 作者：格温（主设计）。本文件是**唯一权威**，6 条职业线子设计必须照此框架填数据，
> 不得自行发明资源/机制/叠层。任何"新增机制"必须先在下方注册表登记。
> 状态：设计阶段。落地前需鱼鱼评审通过。

---

## 0. 设计公理（回应鱼鱼三方批评）

1. **不偷懒**：任何一处都从零审视，不允许"旧代码没被点名就原样留着"。旧技能表全部作废，按本框架重写。
2. **资源不膨胀**：每职业**只有 1 个核心资源**，隐藏线允许第 2 个（且必须跟基础线是"进阶形态"关系，不允许无关新资源）。所有"叠层/印记/槽"一律走**统一标签反应引擎**，不占独立资源位。
3. **数据驱动 + 可扩展 + 可复用**：核心只有两个数据表——`RESOURCE_DEFS`（资源手感）+ `REACTION_TABLE`（标签反应）。本文档自动生成/校验，任何人加一条线 = 向两张表加行。

## 1. 核心资源：6 种手感差异化（不再有"攒点→燃爆"全家桶）

### RESOURCE_DEFS（唯一资源配置表）

| 职业 | key | 名字 | 手感类型 | 上限 | 获取 | 消耗形态 |
|---|---|---|---|---|---|---|
| 刺客 | cp | 连击点 | 小额高频攒点 | 5 | 攻击/技能+1，**暴击额外+1** | 终结技 -3/-5，爆发 |
| 游侠 | energy | 精力 | 自然回 | 100 | 每回合 +30 | 持续花费，保留决策 |
| 法师 | element | 施法立场 | 状态切换 | 3 | 无点数，切立场 | 技能读当前立场 |
| 战士 | rage | 怒气 | 双源积累 | 10 | 出手+1/挨打+1/技能+2 | 满耗爆发 + 中耗防守 |
| 牧师 | faith | 信仰 | 治疗驱动 | 10 | 治疗+2/圣光技+1/受击+1 | 分档消耗 2/3/4/10 |
| 拳师 | chi | 气 | 连段燃料兼受击 | 10 | 连段每段+1/受击+1 | 每段耗气，不一次全耗 |
| 隐藏·龙裔 | dragon_might | 龙力 | 怒气进阶 | 10 | 同怒气 | 龙息终结 |
| 隐藏·时咒 | time_sand | 时之沙 | 回合节拍 | 5 | 回合+1/施法+1 | 时停技消耗 |
| 隐藏·猎印 | hunt_mark | 猎印 | 命中节奏 | 5 | 命中/暴击+1 | 终结技消耗 |
| 隐藏·悼咏 | canticle | 悼咏 | 信仰进阶 | 10 | 治疗/暗影技+1 | 神迹/骷髅海 |
| 隐藏·影步 | shadow_step | 影步 | 暴击/闪避节奏 | 5 | 暴击/闪避+1 | 潜行刺杀 |
| 隐藏·禅意 | zen | 禅意 | 气的进阶 | 10 | 连段/受击+1 | 气力爆发 |

**差异化判据**：同类资源必须满足至少一项"手感轴"不同——数值量级（100 vs 5 vs 3）/ 获取渠道（自然回 vs 行为驱动）/ 消耗形态（一次全耗 vs 分档 vs 持续 vs 立场读取）。

**诗人 = 无专属资源**。诗人的渐强来自 `REACTION_TABLE` 中的 `回声+回声→共鸣` 标签对（见 §2），消耗走魔力。禁止为诗人新增第二套资源。

**法师资源的三线贯通（鱼鱼四问的正面回答）**：法师唯一的资源 = **施法立场（stance）**，
它是一个"当前立场 → 技能读立场 → 立场决定反应/倾向"的状态机，上限 3 档——
**三条线共用这一个状态机，只是立场内容不同**：
- 攻线·元素：立场 = 火/冰/雷（元素标签，走元素反应连环）
- 守线·奥秘：立场 = 奥术共鸣（奥术标签，走共鸣爆破）
- 隐藏·时咒：立场 = 时间之沙（时间标签，走时滞/延迟）

即：**"切换立场"这个动作（element_shift）和它带来的反应触发是法师线共同的认知底子**，
立场内容按线替换。这样"元素亲和"对奥秘/时咒不是死资源——它们照样切立场、照样触发反应，
只是切的是自己的立场、触发的是自己的反应。谁出新线 = 给 stance 加一个立场、给反应表加行。

## 2. 标签反应引擎（唯一机制层，可扩展可复用）

### 核心思想
**"元素反应"是通用机制，不是法师专属**。任何技能可带标签（tag），标签命中目标后留在目标/自身身上；
后续技能带兼容标签时，查 `REACTION_TABLE` 触发结算。结算类型（伤害/增益/控制/延迟/引爆）也是注册表字段，
因此"给新标签定义新反应" = 数据加行，零代码。

### REACTION_TABLE 结构（示例，落地时补全）
```python
REACTION_TABLE = [
  # 攻线·元素（法师系基础标签）
  {"tags": ("fire","ice"),      "name": "蒸发",   "type": "dmg",     "mult": 1.6, "desc": "结算基础伤害并附带冻结概率"},
  {"tags": ("fire","thunder"),  "name": "超载",   "type": "dmg_aoe", "mult": 1.2, "desc": "对目标及相邻造成伤害"},
  {"tags": ("ice","thunder"),   "name": "感电",   "type": "dmg_multi","mult": 1.4, "desc": "造成多次连锁伤害"},
  # 守线·奥秘 —— 同一引擎，标签=奥术印记
  {"tags": ("arcane","arcane"), "name": "共鸣",   "type": "burst",   "per": 0.15, "desc": "引爆目标身上全部奥术印记，每层结算15%"},
  # 隐藏·时咒 —— 同一引擎，标签=时之沙
  {"tags": ("time","time"),     "name": "时滞",   "type": "delay",   "stacks": 1, "desc": "伤害延迟1回合结算"},
  # 诗人系 —— 同一引擎，标签=回声
  {"tags": ("echo","echo"),     "name": "共鸣",   "type": "buff",    "stat": "atk", "val": 0.3, "turns": 3, "desc": "消耗全部回声，全队攻击+30%"},
  # 拳师 —— 同一引擎，标签=连段
  {"tags": ("combo","combo"),   "name": "连段",   "type": "dmg_ramp","per": 0.08, "desc": "连段伤害随段数递增"},
  # 毒系 —— 通用
  {"tags": ("poison","poison"), "name": "毒爆",   "type": "poison_burst", "per": 0.15, "desc": "引爆全部毒层"},
]
```
**判定**：新机制 = 新"结算 type"。新增结算 type 需要 battle.py 加一个分支；新增"标签对"只需在表里加行。
**复用判据**：所有职业的"叠层成长感"（狂意/龙鳞/回声/暗影/连段）必须落到 `dmg_ramp` / `burst` 这种已有结算上，
禁止各自发明平行机制。

### 技能 schema（纯数据，所有职业同一格式）
```python
{
  "sk_xxx": {
    "name": "汉名", "lv": 30, "mp": 15, "power": 1.0,
    "kind": "物理|魔法|真伤|治疗|增益|被动|召唤",
    "tags": ["fire"],            # 标签 → 反应引擎
    "targets": "single|front|all|ally",
    "reach": 1, "cd": 0, "charge": 0,
    "cost": {"res": 2},           # 核心资源消耗（res 自动读职业资源key）
    "moves": [                     # 效果列表（数据驱动）
      {"type": "dmg", "mult": 1.0},
      {"type": "buff", "stat": "atk", "val": 0.3, "turns": 3},
      {"type": "cond", "if": "enemy_burn", "mult": 1.3},   # ⚡条件
    ],
    "passive": {...},
    "desc": "玩家可见描述（消耗行由渲染器自动拼）"
  }
}
```

## 3. 六条线节奏分工（由主设计定，子 agent 只填数据）

| 线 | 标签体系 | 攻线节奏 | 守线节奏 | 隐藏线节奏 |
|---|---|---|---|---|
| 战士 | 怒气+斗势标签 | 狂战·渐强+爆发(满怒) | 盾卫·平稳(受击回怒) | 龙裔·灼烧DOT渐强+真伤爆发 |
| 法师 | 元素/奥术/时间标签 | 元素·反应连环爆发 | 奥秘·共鸣平稳 | 时咒·时间控制爆发 |
| 游侠 | 标记/毒/疾风标签 | 林语·毒藤铺场渐强 | 风行·高速连射爆发 | 星语·占星节奏平稳 |
| 牧师 | 圣光/歌声/亡者标签 | 诗人·回声渐强团辅 | 神谕·单奶神威平稳 | 暗影·骷髅海铺场爆发 |
| 刺客 | 连击点/毒/影步标签 | 影舞·高连击快爆发 | 毒刃·毒层渐强引爆 | 暮影·影步一击必杀 |
| 拳师 | 气/连段/禅意标签 | 格斗·连段渐强 | 磐石·受击反制平稳 | 苦修·禅意慢热高爆 |

**（注：此表与上一版一致，因为方向是对的；变化的在"实现层"——全部落进标签反应引擎，不再各造叠层。）**

## 4. 旧技能表处置

- **全部作废**，按新 schema 重写。旧技能名如确需保留（玩家认知），只保留"名字"，机制按新框架重做。
- REMOVED_SKILLS 表登记被删技能，返还已投入的升级点数（老玩家存档零迁移原则）。

## 5. 落地范围（需新增代码，数据驱动）

| 代码 | 用途 |
|---|---|
| `game/data/mech_registry.py`（新） | RESOURCE_DEFS + REACTION_TABLE + 技能 schema 校验 fail-fast |
| `game/core/react.py`（新） | 标签反应结算引擎（消耗标签→查表→结算；新结算 type 在此扩展） |
| `game/core/stance.py`（新） | 法师元素亲和状态切换（当前立场→技能读取立场→反应） |
| `game/battle.py` | moves 效果列表执行器（dmg/buff/cond/dot/cc/summon 分发表） |
| `game/data/skills.py` 等 | 6 线技能数据重建为统一 schema |
| `scripts/verify_mech.py`（新） | 校验：每技能引用标签存在/反应表有兜底/无零消耗/黑名单/SKILL_UP 覆盖率 |

**不新增**：每技能自定义逻辑、职业特判 if 分支、第二套资源。
