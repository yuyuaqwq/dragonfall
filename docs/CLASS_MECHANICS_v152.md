### 0.1 七形式（不可变，职业身份）

形式的区分标准不是"数学结构必须完全不同"（做不到），而是**载体位置、时间尺度、决策问句三者不同**。

### 0.4 出手节奏（CTB 独有，职业身份）

CTB 下"出手后多久轮到自己"是核心决策。这是职业身份，不是硬枷锁——每线保留 1~2 个异型节奏技能作"变奏"（表中标 `*`）。

```
ct_cost_mult（技能行动成本系数，缺省 1.0）
  0.7 快技 → 更快轮到自己
  1.0 标准
  1.3 重技 → 更慢轮到自己
```

| 节奏型    | 主系数             | 职业       | 理由                                      |
| ------ | --------------- | -------- | --------------------------------------- |
| 疾速     | 0.7             | 刺客、游侠    | 多动滚雪球 / 铺印记                             |
| 标准     | 1.0             | 战士、牧师、拳师 | 稳；拳师推条需要出手频率                            |
| 沉重     | 1.3             | 法师       | 站桩读条                                    |
| **变奏** | 0.7 / 1.0 / 1.3 | 吟游诗人     | **换歌 0.7、吟唱 1.0、终章 1.3——节奏切换就是诗人的形式本身** |

> v151 把诗人归为"标准 1.0 为主"，但诗人的技能表里 0.7 占多数，自相矛盾。本版改称「变奏型」，把矛盾变成设定。

**落地口径（修正 v151 的低估）**：`_ct_cost(spd)` 现有签名只接收速度，拿不到技能。接入需改签名为 `_ct_cost(spd, mult=1.0)`，并同步 **12 处调用点**：`battle.py` 2 处、`instance.py` 5 处（其中 4 处用于计算入场 CT，此时无技能，走缺省 1.0）、`scripts/smoke_ctb_instance.py` 2 处、`tests/test_ctb_audit.py` 1 处、另有 `scripts/sim_ctb_balance.py` / `sim_audit_a4.py` 需回归。**不是"加一行"**。

### 0.5 数值口径（杜绝虚标与歧义）

```
单段满级倍率 = base × 1.40
总 eq        = base × 1.40 × hits × (0.8 若真伤)
```

**四条记法铁律**（v151 全部违反过）：

1. `base` = **Lv.1 裸倍率**，唯一真值源。
2. `hits` = 段数，独立成列。`(×3)` 这类写在 eq 里的记号**一律废弃**（v151 有 2 个技能把段数乘进了 eq、7 个没乘，程序无法统一解析）。
3. **AOE 折扣折进 `base`**：`base_aoe = 裸值 × 0.6`，并在备注标 `[AOE]`。不在 eq 层另乘。
4. **`总eq` 列由脚本生成，禁止手写。**

**天花板**（单发，无条件下）：

| 档  | 等级    | 天花板 | 条件倍率上限 |
| -- | ----- | --- | ------ |
| 基础 | 1-28  | 2.0 | 2.6    |
| T1 | 32-58 | 2.5 | 3.25   |
| T2 | 62-88 | 3.5 | 4.55   |
| T3 | 90-98 | 4.5 | 5.85   |

> **条件倍率**（如"战意≥8 时 ×1.5"）不计入裸 eq，但要求 `裸eq × 条件 ≤ 条件倍率上限`。v151 没区分这两层，导致 元素湮灭 3.36 堂而皇之挂在 T1（上限 2.5）。

**其它红线**：

- **真伤**：每线 ≤2 个，标 `真伤`，总 eq 已 ×0.8。
- **多段**：`总eq ≤ 同档单体 max × 1.15`。
- **控制递减**：同目标 3 次行动内 100% → 50% → 免疫；首领固定 1 回合。
- **MP**：`mp=0` 仅允许三类——纯被动、形态切换、以及**以机制层数为消耗的技能**（如战士「冷静」花战意）。其余一律 >0。
- **CD 或代价二选一**：伤害技必须有 CD；**若无 CD，则 mp 不得低于 6（基础层）/ 10（转职后）**，用 MP 做节流。不允许"无 CD 且低 mp"的伤害技（v151 每线有 4~~5 个 mp3~~5 无 CD 的裸伤技，构成一键循环最优解）。

### 0.8 CTB 计时口径（"持续 N 回合"到底怎么算）

**这是本文档最容易被误读的一节。** CTB 是伪即时制，没有传统回合制的"轮"概念，所以"持续 3 回合"必须定义清楚。

#### 0.8.1 引擎现况：一个"回合"是什么

```
player_turn()  →  self.round += 1  →  玩家行动 1 次
                                   →  _after_actor_ct("p")  玩家 ct += cost，其余 ct -= cost
_enemy_phase() →  while 存活敌人中最小 ct <= 0（上限 8 连动）：
                        该敌人行动 1 次 → _after_actor_ct("e")
                  →  _end_round()          ← buff turns -1，每"回合"只调这一次
```

**一个回合 = 玩家行动 1 次 + 该回合内所有轮到的敌人各行动 0~N 次（硬上限 8 连动）。**

推论：**敌人速度越快，一个回合内敌人打你越多，但你的"3 回合"buff 覆盖的敌人行动次数也越多。**
反过来，敌人慢时你的 buff 会"浪费"在没有挨打的回合上。

#### 0.8.2 引擎现况：五类计时语义并存

`_end_round()` 里有一串豁免列表，说明"回合递减"并非唯一口径：

| # | 语义 | 递减时机 | 适用 | 代码位置 |
| --- | --- | --- | --- | --- |
| 1 | **回合制**（默认） | `_end_round` 每回合 -1 | atk_up / matk_up / reduce_all / shield / hot | `battle.py:5341` |
| 2 | **行动级** | 由行动消费点 pop，**不在回合末递减** | stun / freeze | `battle.py:5310` |
| 3 | **层数标记** | 不按回合减，触发反应清除或战斗结束 | fire_mark / ice_mark / thunder_mark | `battle.py:5316` |
| 4 | **挂条 bar** | `bar_tick` 回合始按 `decay_per_turn` 衰减 | shaken（破绽）/ curse | `battle_bars.py:133` |
| 5 | **受击计数**〔v151 时刻制〕 | `_damage_player` 实际受击 -1，豁免回合递减 | def_up / def_up_big / dodge_pot / thorns_pot 等防御类 | `battle.py:1915 / 5833` |

第 2 类的注释解释了为什么必须这样：

> 控制类 buff（stun/freeze）是"行动级"控制——由行动消费点负责 pop，不能在回合结束时递减：
> 否则施放当回合若敌方尚未轮到行动（CTB 下敌方该轮未行动）会被直接吞掉，**眩晕永远不生效**。

第 5 类是 **v151 已经落地的改造（鱼鱼拍板）**，注释写明理由：

> 铁壁药剂/岩壁药剂/影步药剂/荆棘药剂/技能铁壁 等防御/受击类 buff 不再按玩家回合递减，
> 改为"实际受击 N 次后消失"——**防的是敌方出手，就按敌方出手数计时，不受速度差影响。**

#### 0.8.3 问题：回合制 buff 在 CTB 下会被速度差稀释

同一个"减伤 30%，3 回合"，实际覆盖量随敌方速度剧烈波动：

| 敌方速度 | 一个回合内敌人行动 | "3 回合"实际挡下 |
| --- | --- | --- |
| 0.5×（慢） | 0~1 次 | 1~2 次攻击 |
| 1×（同速） | 1 次 | 3 次攻击 |
| 2×（快） | 2 次 | 6 次攻击 |
| 3×（很快） | 3 次 | 9 次攻击 |

**同样是"3 回合"，实际收益差 4~9 倍。** 这让所有回合制 buff 的强度不可控——
对快敌超模，对慢敌白给。

#### 0.8.4 v152 的计时口径规范（本文档统一约定）

按**"这个效果防的是谁/作用于谁"**来选计时单位，而不是一律写"回合"：

| 效果类型 | 计时单位 | 文档中写法 | 例子 |
| --- | --- | --- | --- |
| 自身攻击/暴击类增益 | 自己的出手次数 | "持续 N 次出手" | 鹰眼锁定、狂热 |
| 敌方减益（减速/降防/易伤） | 敌人的行动次数 | "持续 N 次敌方行动" | 冰锥减速、死亡标记 |
| 眩晕/冻结/跳过 | 行动级 | "跳过 N 次行动" | 冻结、破防 |
| **防御/减伤/护盾/反伤** | **受击次数**〔沿用 v151 时刻制〕 | "可挡 N 次受击" | 铁壁、厚土、圣光铠甲 |
| 印记、标记类挂账 | 不衰减 | "触发反应清除 / 战斗结束" | 元素印记、猎印 |
| 挂条（破绽） | bar 的 `decay_per_turn` | "每回合 -N" | 破绽条 |
| DOT（毒/灼烧/流血） | 每次玩家行动 = 一回合 | "持续 N 回合" | 毒 2 层、流血 2 层 |

> **判定口诀**：效果**防的是敌方出手** → 用受击次数；效果**作用于敌方** → 用敌方行动次数；
> 效果**作用于自己** → 用自己的出手次数。只有 DOT 沿用"玩家行动 = 一回合"的既有闸门
> （`_tick_dots` 的 `_dot_pending`，`battle.py:5096`）。

#### 0.8.5x 回合制计时是架构债：唯一自洽的基准是 ct 轴

> **本节结论被鱼鱼推翻过一次，现在是修正版。** 初版分析认为"自身增益按玩家出手次数递减是自洽的"——
> 这是错的，错在漏了 §0.4 自己写的 **ct_cost_mult**：快技 0.7 出手 3 次只流逝 2.1 个 cost，重技 1.3 出手 3 次流逝 3.9 个 cost，
> **同样"3 次出手"覆盖的绝对时间差 86%**。一旦出手有耗时，"按次数计时"和"按时间计时"就脱钩了，全部按次数递减的 buff 都不自洽。

引擎的时间模型（v130.10 绝对时刻）：

```
cost = BASE_DELAY / min(spd, SPD_CT_CAP)     # BASE_DELAY = 100
行动者 ct += 自身 cost；其余所有单位 ct -= 该 cost   （时间流逝）
```

**每个单位的行动频率都锚定在这条 ct 轴上——唯独 buff 计时没有。** buff 按行动事件次数递减，
而事件的 ct 间隔被两个因素拉扯：敌我速度差、以及自身 ct_cost_mult（快/重技）。
结果就是：快技流玩家的 buff 实际时长比重技流短近一半，敌方 debuff 的价值随敌速波动 1~9 倍。

**正解：buff 的持续时间锚定 ct 轴（时刻制），对外文案仍显示"回合"。**

```
Battle 新增 self.world_ct（全局时钟）：每次 _after_actor_ct 时 world_ct += 该次行动的 cost
buff 新增 expire_ct 字段：施加时 expire_ct = world_ct + turns × ROUND_CT
过期清扫：每次 world_ct 变动后，扫描并摘除 expire_ct <= world_ct 的 buff
ROUND_CT（"1 回合"的 ct 长度）= BASE_DELAY，即固定常数 100
```

这样做的正确性：

| 原来的扭曲 | 时刻制下的行为 |
| --- | --- |
| 快技流 buff 缩水（3 次快技只过 2.1 ct） | buff 覆盖固定 300 ct，**快攻手在这段时间里多出手**——这正是即时制语义：buff 是一段时间，不是几个事件 |
| 敌速慢则 debuff 浪费、敌速快则超值 | debuff 时长与敌速无关，只表达"这段时间内它变弱了" |
| 减速敌人身上 debuff 掉速不可控 | 减速 = 该敌 cost 变大 = 单位 ct 内行动少，debuff 到期时间不变——**"打不着但一直弱"**，语义正确 |

**玩家认知不变**：战报和技能描述仍写"3 回合"（1 回合 = 100 ct 的固定换算），
只是底层从"数 3 次玩家行动"换成"数 300 ct"。玩家不需要知道 ct 存在。

**CD 例外**：技能冷却的语义本来就是**事件间隔**（"用一次要歇 N 次出手"），不是持续时间——
按玩家出手次数递减是正确的，维持现状。同理 DOT 的"每次我行动结算一跳"也是事件语义，保留；
但 DOT 的**持续时长**（挂几层毒跳几轮）应随 expire_ct 走。

**改造清单（供排期）**：

| # | 改动 | 位置 |
| --- | --- | --- |
| 1 | 新增 `world_ct`，行动时累加 cost | `_after_actor_ct` |
| 2 | buff 结构加 `expire_ct`；施加时换算 turns → ct | buff 写入点（药水/食物/技能/装备/boss） |
| 3 | 过期清扫（替代 _end_round 的 turns-1 循环） | `_end_round` 改为只做 CD 递减 + 摘除过期 buff |
| 4 | 战报换算显示（"剩余约 N 回合" = ceil(expire_ct-world_ct / 100)） | buff 展示点 |
| 5 | 序列化兼容（老存档 turns → expire_ct 迁移） | `_to_state` / `_from_state` |
| 6 | 豁免名单里的事件语义类（stun/freeze/mark/shaken/受击计数）**不动** | — |

#### 0.8.6 "回合"的最终地位：拆成两个东西，其中一个已经死了

时刻制落地后，"回合"这个名字下其实一直混着两个职责，必须拆开：

**① 时间职责 —— 死了。** 以下几处目前都在用 `self.round` 当时间轴，时刻制下全部移交 `world_ct`：

| 现况 | 位置 | 时刻制写法 |
| --- | --- | --- |
| buff 持续（turns-1） | `_end_round` | expire_ct（§0.8.5x 改造清单 #2） |
| boss 机制节奏（`r = self.round` 传给 BOSS_MECHS） | battle.py:4281 | 阶段/技能按 world_ct 间隔触发 |
| 宠物技能间隔（`round % interval`） | battle.py:4738 / 4765 | `world_ct % interval_ct` |
| DOT 适应消退（2 回合未叠层 -4%） | battle.py:4970 | X ct 未叠层则消退 |
| 新手保护（round ≤ 1） | battle.py:5750 / 5888 | world_ct ≤ 100（开局阶段） |

**② 交互职责 —— 活着，但它叫「行动」不叫「回合」。**
QQ bot 是异步文字交互：玩家发一条指令 → 世界推进到玩家的下一个行动点 → 敌方按 ct 决定动几次 → 等下一条指令。
这个"行动窗口"是交互的结构，**必须存在**，否则玩家没有输入时机。

但要意识到：**传统回合制里 round = 所有单位各行动一次；CTB 里这种结构根本不存在**
（敌人可以在一个窗口里连动 8 次，也可以一次都不动）——存在的只有 **turn（行动）的序列**。
"回合"这个叫法在 CTB 下描述的是一个不存在的东西。

**落地约定**：
- 引擎：`self.round` 保留字段（序列化兼容），语义改为"玩家行动计数"，建议择机改名 `self.turn_count`
- 设计文档：内部表述统一用「行动」（交互）和「ct / 回合换算」（时间）两个单位，不再用"回合"指代时长
- 玩家侧文案：可继续显示"回合"（= 100 ct 的固定换算，玩家熟悉），但这是显示层的皮，不是机制层的骨

> 顺带收益：原来"档 2 敌方 debuff 按该单位行动递减"的方案**不需要了**——按 ct 过期天然对敌我一视同仁，
> 也不依赖 e_buffs 的 per-unit 化（per-unit 仍值得做，但那是解决"debuff 挂在哪个敌人头上"的归属问题，与计时解耦）。

## 一、战士 — 叠层「战意」

**形式**：战意叠在自己身上。**持有即强，常态不消耗**；每线各有 1~2 个「兑现技」（主动消耗战意换即时效果），这是例外不是常态。

```
战意 0-10 层
  获取：普攻/技能命中 +1，击杀 +2，受击 +1
  持有收益：每层 攻击 +4%（满层 +40%）
  持有代价：每层 受伤 +2%（满层 +20%）     ← 越强越脆

    狂暴中：普攻双段 2×70%，吸血 25%，攻击 +20%

```

## 二、法师 — 记账「元素印记」

**形式**：三系印记**分类记在敌人身上**（多条账目），可组合结算。与拳师「充能」的区别：拳师是单条进度推满即清，法师是多本分类账，怎么组合才是决策。

```
元素印记（火/冰/雷，每系 0-3 层，记在单个敌人身上）
  记账：火系技能 → 火印 / 冰系 → 冰印 / 雷系 → 雷印
  衰减：**无**（生命周期 = 触发反应清除，或战斗结束）
  层数作用：该系结算倍率 1层 ×1.0 / 2层 ×1.2 / 3层 ×1.4

  ⚠ 印记绝不能按回合/行动衰减。引擎 `battle.py:5316` 的豁免注释写明了原因：
    "CTB 下每回合都正常结束，印记施放当回合就被清掉，元素反应（挂印→异系触发）体系整体失效。"
  引擎现况里 fire_mark / ice_mark / thunder_mark 已在豁免名单中（不参与 _end_round 递减），
  设计上必须与之保持一致——否则"挂印 → 异系引爆"这条链路永远走不通。

  结算（主动引爆，清空参与结算的印记）：
      火印 + 冰印 = 蒸发   伤害 ×1.30
      雷印 + 火印 = 超载   转为全体 AOE
      冰印 + 雷印 = 冻结   目标跳过 1 次行动
      雷印满 3 层 = 感电   连击 +1（印记保留，不结算）
```

> **v151 的两处修正**：① 明确"层数决定倍率、系别决定反应类型"（v151 里"印记满 3 层"和"三系同时满"混用，语义不清）；② 感电由"雷印+雷"改为"雷印满 3 层"——同系反应与三角克制的异系逻辑冲突。
> **关于衰减**：v152 初稿写了一句"每行动 2 次 -1 层（防无限堆积）"，**这句是错的**，已删除。
> CTB 下回合制衰减会让印记挂上即失效，引擎也早已把三个 mark 放进 `_end_round` 豁免名单。
> 印记会不会无限堆积，靠的是 §2 的**结算即清空**——每个结算技都是印记的出口，不是靠衰减。

**决策问句**：给谁记账？记哪系？什么时候结？

**代价**：站桩读条（沉重 1.3），架设态受击 +20%、不可普攻。

## 三、游侠 — 预算「专注」

**形式**：**每回合重置的预算**——像零花钱，这回合不花完就浪费。**这是真正消灭"攒满→消耗→归零"的关键改动。**

```
专注 0-100
  每回合开始：专注重置为 100（不累积、不继承、不跨回合）
  技能消耗专注（见「专注」列）；专注不足 → 该技能不可用
  结余奖励：回合结束时专注 ≥40 → 下回合首次技能暴击 +15%（【凝神】）
```

> **v151 的问题（P0）**：它写的是"精力 0-100，每回合回 30，满 100 → 凝神屏息：**归 0**，下回合段数 +1"——这正是文档开篇宣称要消灭的"攒满→消耗→归零"资源条；而且 21 个游侠技能**没有一个标注精力消耗**，三档预算（连射/压制/终结）定义了却无处挂载，系统空转。
>   
> 本版改为每回合重置：**不累积就没有"攒"，不归零就没有"消耗→归零"**。结余奖励是"持有即奖"，不是"攒满放"。

**决策问句**：这 100 点怎么花？铺三个小技还是憋一个大的？要不要留 40 点换暴击？

**代价**：身板脆（后排）；专注是硬约束，大技用了小技就没得用。

## 四、牧师 — 负载「信念」

**形式**：信念是牧师**当前承担的负荷**。持有越高治疗越强，但自身越危险。与战士战意是镜像——战士是"越勇越猛"，牧师是"越用力越疲惫"；区别在于**信念会自动下降、且有主动卸负**，它是**负债**不是资产。

> **v151 的牧师章节（P0）**：「核心机制」小节是一句残留的 prompt 文本（"吟游诗人转职后职业叫什么…"），整章没有任何机制定义。唯一撑起深度的「治疗耐受」只在技能描述里以"清 1 层耐受"出现，衰减公式、层数上限、恢复规则**全部未定义**——"层"是个没有定义的单位。本版重写。

```
信念 0-100（负载）
  增加：每次治疗 +(治疗系数 × 25)；目标生命 <30% 时额外 +15（急救代价）
  减少：每回合末 -15；主动「卸负」-30
  负载档位：
      0-30   清醒   治疗量 ×1.00，自身受伤 ×1.00
      31-70  专注   治疗量 ×1.25，自身受伤 ×1.15
      71-99  透支   治疗量 ×1.50，自身受伤 ×1.35
      100    过载   强制清空信念 → 全队回复（值 = 清空前信念 × 0.8% max_hp）
                    随后 2 回合【力竭】：治疗量 ×0.5，信念不再增加
```

**过载是双刃剑**：它给你一次全队大奶（救场价值），但之后 2 回合力竭（危险窗口）。所以有时候你会**故意**堆到 100 去换这一次救命。这就是牧师的决策。

**决策问句**：我现在欠多少？该主动卸负，还是硬扛到过载换一次全队大奶？

**代价**：负载越高自己越脆，且过载后有 2 回合空窗。

## 五、刺客 — 计数「连段」

**形式**：连段是**命中计数**，不是货币。

```
连段 0-10
  命中 +1 段
  未命中（miss/被闪避）→ 连段减半（向下取整）
  被控、跳过回合      → 连段归零
  每段：暴击率 +3%（满段 +30%）
  终结技：伤害 ×(1 + 0.10 × 连段)，结算后连段归零
```

> v151 的断连是"miss/被闪避 → **归零**"。这是敌方属性导致的、玩家完全无法预防的 100% 全损，而缓解手段「暗影之心」要 Lv60 才有。配合 0.7 疾速节奏（出手多 = 断连机会多），风险高到没有收益可对冲。
>   
> 本版：**未命中只减半**（可控损失），**被控/跳过回合才归零**（玩家能避免的部分才严惩）。

**决策问句**：续连还是收割？

**代价**：断连即损；连段越高越舍不得收，但收割窗口稍纵即逝。

## 六、拳师 — 充能「破绽」

> **关于命名与 id**：引擎 id 是 `cls_wu_seng`（拼音"武僧"），但**显示名一直是拳师**——`battle.py:963` 注释「拳师（v130.2c 修正 class id）」、`dialogues.py` 就职对话「🥋 拳师——以拳证道的武斗家」、`affixes.py` 词缀线「拳师·攻线/爆发流」均可证。**id 与显示名不一致是长期遗留问题**（下称"老毛病"），`classes.py` 里还留着 v112 的批注：「拳斗士→格斗士、武斗师→拳术师（与隐藏线『武僧』词族拉开）」。
>   
> 本版沿用显示名**拳师**。id 建议日后单独更名（`cls_quan_shi`），但**不要借机把职业改成"武僧"**——那会撞进 v112 刻意避开的词族，还会与已删除的隐藏职业 `cls_wu_sheng`（苦修士·武僧 → 淬势者）混淆。

**形式**：破绽是挂在敌人身上的**单条进度条**，推满即清。与法师「记账」的区别：法师是多本分类账、怎么组合是决策；拳师是一条进度、推不推得满才是决策。

```
破绽条 0-50（挂敌人身上，全队共享；引擎字段 enemy_bar.shaken）
  推条：技能注入（值见各技能「推条」列）
  衰减：每回合 -4（decay_per_turn = 4）
  推满 → 目标【破防】：跳过下 1 次行动，破绽清零
  阈值递增：每次触发后 ×1.35，封顶 ×2.5（= 125，防无限控）
  免疫窗口：触发后 1 回合内不再积蓄（immune_turns = 1，防连控锁 Boss）
  阶段转换：保留 50% 积蓄（phase_preserve_pct = 0.5）
  自锁防护：no_inject_on_trigger —— 触发当回合注入 = 0（防「晕→追颅→又满→再晕」）
  **不吃异常免疫**：v139 起这就是拳师线对付免疫巨兽的**唯一软解**
  换目标：原目标进度保留但继续衰减
```

> **v152 初稿在这里写错了，已回退引擎现况。**
> 引擎 `battle_config.py` 的 `ENEMY_BAR_CFG["shaken"]` 现况是
> `max 50 / decay_per_turn 4 / threshold_base 50 / threshold_inc ×1.35 / threshold_cap ×2.5`，
> 且注释里写明了注入量级：**「三连击破 +15 / 碎颅势 +15 / 旋风踢 +5 每目标 / 无影连打每段 +3」**。
>
> v151 文档把注入量写成了 **+1**（差一个数量级），我 v152 初稿改成 +10 仍偏小。
> **真正的病灶是 v151 的 +1 注入配上 decay 4 —— 净 −3/回合，永远推不满。**
> 按引擎现况的注入量（三连击破 +15）重算：**净 +11/回合，约 4~5 回合触发一次破防**，数值本来就成立。
> 本版因此不再自创数值，直接沿用现况，只把 v151 写错的技能注入量改对（见下表「推条」列）。

## 七、吟游诗人 — 驻留「旋律」

**形式**：诗人唱一首歌，旋律作为**持续光环**驻留战场，直到换歌。诗人没有资源条，他的决策是"现在该唱哪首"。

```
驻留旋律（同时只能 1 首）
  唱出   → 旋律驻留，全队获得光环，持续到换歌（换歌 = 唱另一首，0.7 快技）
  吟唱   → 继续唱同一首，强度层 +1（上限 5），1.0 标准技
  强度层 → 每层光环效果 +20%（线性）
  强度 5 → 触发该旋律的【终章】效果
  换歌   → 旧光环消失、新光环生效、强度层清零
  代价   → 旋律驻留期间不能普攻（专心演唱）
```

> v151 的三处修正：①「换歌」没有技能条目——本版明确：**"唱某首旋律"这个动作本身就是换歌**，不需要额外的换歌技能；②「强度层」零定义——本版给出上限 5、每层 +20%、满层触发终章；③ §0.4 说诗人"标准 1.0 为主"但技能表 0.7 占多数——本版改称「变奏型」，把矛盾变成设定。

**决策问句**：唱哪首？换歌还是继续吟唱强化？

**代价**：诗人自身脆弱（后排），且旋律驻留期间不能普攻。

## 九、元素属性与抗性体系（七职业的底层规则）

> 现状诊断（沿用 v151）：代码里已有元素属性（`element`: fire/ice/thunder/dark）+ 元素反应 + 抗性概念（`elem_res`/`abyss_res`/`dot_res`/`immune_dots`/`adapt`），但**怪物侧没配数据**，导致"火/冰/雷"只是三个图标。本章把底座补齐。

### 9.1 元素属性（伤害的"属性轴"）

| 属性        | 对应 DOT    | 克制                | 被克  | 挂载              |
| --------- | --------- | ----------------- | --- | --------------- |
| 火 fire    | 灼烧 burn   | 克冰（对冰冻目标 +25%，解冻） | 被雷克 | 元素印记·火印 / 狂战灼烧  |
| 冰 ice     | 冻结 freeze | 克雷（对雷印目标 +25%，打断） | 被火克 | 元素印记·冰印 / 咒缚师冻结 |
| 雷 thunder | 感电        | 克火（对灼烧目标 +25%）    | 被冰克 | 元素印记·雷印 / 咒缚师麻痹 |
| 暗 dark    | 腐蚀 corros | 无克制，专打高防（真伤轴）     | 无   | 毒刃腐蚀真伤          |

**克制规则**（三角循环）：火 → 冰 → 雷 → 火。克制命中时伤害 ×1.25，并触发一次对应反应（**蒸发 / 超载 / 感电 / 冻结**四者之一，按印记组合决定）。

> v151 的 §9.1 只列了"蒸发/超载/感电"三种，**漏了冻结**，与 §2 反应表的四条对不上。本版补齐为四条。

### 9.2 抗性（伤害的"减免轴"）

| 抗性            | 减免对象           | 上限  | 现状        |
| ------------- | -------------- | --- | --------- |
| `elem_res`    | 火/冰/雷 三系魔法伤害   | 50% | 玩家有，怪物无   |
| `abyss_res`   | 暗系伤害           | 50% | 玩家有，怪物无   |
| `dot_res`     | 毒/灼烧/流血/腐蚀     | —   | 怪物无       |
| `immune_dots` | 指定 DOT 类型直接免疫  | —   | 怪物无       |
| `adapt`       | 连续叠层后 DOT 耐受递增 | 95% | 机制在跑，缺基础值 |

**要补的怪物数据**（三个字段：`elem_res` / `dot_res` / `immune_dots`）：

- **火焰怪**：`elem_res` 火 0.5、冰 0 → 逼玩家换系。
- **免疫怪**：`immune_dots: ["burn"]` → 狂战线的「内燃」（火免转真伤）才有意义，否则这个机制白设计。
- **高防 Boss**：`immune_dots: ["poison"]` → 毒刃线的腐蚀真伤轴才是唯一解，否则 DOT 无脑叠。

### 9.3 DOT 结算（毒/灼烧/流血/腐蚀）

沿用 `battle_config.py` 的 `DOT_DEFS` + `_tick_dots` 混合公式：

```
每层每回合伤害 = (atk×a + matk×m + max_hp×h) × 层数 × mult × (1 - 总抗)
总抗 = min(0.95, dot_res + adapt)      # 连续叠层 adapt 递增，2 回合没叠 -4% 消退
immune_dots 命中 → 直接移除不结算
corros（腐蚀）→ true_dmg 分支，绕过 def/mdef（但不豁免目标异常抗性）
```
