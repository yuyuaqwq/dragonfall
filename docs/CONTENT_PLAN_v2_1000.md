# 《剑与魔法》千元素内容工程 · 策划案 v2.0

> 版本：v2.0（2026-08-10）
> 目标：随机惊喜层从 ~70 元素 → **1100+ 元素**，且**未来加内容零代码**（纯数据扩展）。
> 核心理念：**不是堆 1000 条文案，而是造一台"内容机器"**——数据驱动 + 模板引擎 + 规则系统。

---

## 〇、设计哲学：为什么必须数据驱动

### 0.1 现状诊断（为什么你觉得少）

| 层 | 现状 | 问题 |
|---|---|---|
| 静态内容 | 怪物299 / 材料459 / 装备112 / NPC213 / 地图116 | 量大但玩家感知弱（要主动找） |
| **随机惊喜层** | 探索事件12 / 彩蛋5 / props55 / 隐藏怪6 | **只有 ~78 个**，且扩展要改代码 |

玩家日常感知 = 随机惊喜层。这层太薄 = 世界显得空。

### 0.2 致命瓶颈（v1.x 策划案的隐藏缺陷）

现有 `EXPLORE_EVENTS` 虽是数据表，但**处理逻辑在 combat.py 用 if-elif 硬编码**：
```python
if eid == "treasure": ...
if eid == "merchant": ...
if eid == "spring": ...
# 加一个新事件 = 改代码 + 改测试 + 全量回归
```
**手写 1000 条文案 + 1000 个 if 分支 = 灾难**。必须先把"内容"和"逻辑"彻底分离。

### 0.3 三层架构（本策划案的骨架）

```
┌─────────────────────────────────────────┐
│ L2 注册层：自动加载 + 校验 + 建索引      │  ← 新数据文件放进去自动生效
│   (content.py / _assembly.py 扩展)       │
├─────────────────────────────────────────┤
│ L1 引擎层：模板解释器 + 规则匹配器       │  ← 唯一写代码的地方（12 种模板）
│   (event_templates.py / rule_engine.py)  │
├─────────────────────────────────────────┤
│ L0 数据层：纯数据文件（无逻辑）          │  ← 未来 95% 的扩展发生在这里
│   events_fun.py / events_rare.py /       │
│   rules_*.py / props_*.py / monsters     │
└─────────────────────────────────────────┘
```

## 一、引擎层（L1）：事件模板系统

### 1.1 模板机制（消灭 if-elif）

事件 = **模板 + 参数 + 文案变体池**。引擎统一执行：

```python
# 数据层（L0）新增一个事件 = 一条 dict：
{
    "id": "ev_windmill_sack",
    "template": "loot_material",        # 复用现有模板
    "weight": 4,
    "maps": ["windmill_plain"],          # 可选：限定地图
    "cond": {"time": "day"},             # 可选：条件
    "params": {"mats": [("面粉", 0.5), ("草药", 0.3), ("金币", 0.2)], "n": 1},
    "texts": [                            # 文案变体池（引擎随机挑一条）
        "风车吱呀转着，你摸进磨坊，找到半袋被遗忘的面粉。",
        "磨盘底下滚出一只陶罐，里面竟装着晒干的草药！",
    ],
}
```

### 1.2 初始模板清单（12 种，一次开发永久复用）

| # | 模板 | 行为 | 参数 |
|---|---|---|---|
| T1 | loot_gold | 金币 | `{min, max}` |
| T2 | loot_material | 概率掉落材料 | `{mats: [(id, 概率)]}` |
| T3 | loot_item | 概率掉落物品/图纸 | `{items, chance}` |
| T4 | heal_full | 回满血蓝 | `{}` |
| T5 | damage | 扣血（陷阱类） | `{pct, min}` |
| T6 | buff | 临时增益 | `{buff, dur}` |
| T7 | set_flag | 记隐藏线索/见闻 | `{flag, value}` |
| T8 | dialog | 纯氛围对话 | `{texts}`（变体池） |
| T9 | spawn_hidden | 触发隐藏怪战斗 | `{monster_id}` |
| T10 | shop | 限时买卖（流浪商人） | `{pool, discount}` |
| T11 | quest_hook | 挂接任务推进 | `{quest, stage}` |
| T12 | combo | 组合多个效果 | `{steps: [子模板]}` |

### 1.3 兼容改造（v97.3 必做）

- 现有 12 个探索事件 + 5 个彩蛋 **全部改造为模板实例**（行为不变，只是搬家）
- combat.py 的 if-elif 分支 → `TEMPLATES[eid].execute(...)` 一行分发
- 改造后：**加新事件 = 加一条数据，零代码零测试改动**

## 二、引擎层（L1）：行为彩蛋规则系统（全新）

### 2.1 概念：规则 = 条件→反应，挂"触发器"

玩家每次关键动作后，引擎检查该动作的规则表，命中则触发惊喜：

```python
{
    "id": "rule_heal_on_monster",
    "trigger": "use_item",              # 触发器（见 2.2）
    "cond": {"item": "治疗药水", "target": "monster"},
    "chance": 0.5,
    "action": {"type": "dialog", "texts": [
        "你把治疗药水泼向哥布林——它愣住了：『你……你是不是搞错了？』",
        "药水洒在怪物脸上，它居然露出嫌弃的表情，伤害反而+10%！",
    ]},
}
```

### 2.2 触发器挂点（11 个，覆盖所有高频动作）

| # | trigger | 触发时机 | 规则数 |
|---|---|---|---|
| G1 | explore_done | 探索结束后 | 10 |
| G2 | battle_win | 战斗胜利后 | 8 |
| G3 | battle_use_item | 战斗中使用道具 | 5 |
| G4 | gather_done | 采集/挖掘/垂钓结算后 | 8 |
| G5 | craft_done | 锻造/炼金/烹饪后 | 6 |
| G6 | move_enter | 进入新地图时 | 8 |
| G7 | talk_npc | 与 NPC 对话后 | 6 |
| G8 | quest_deliver | 交付任务后 | 4 |
| G9 | buy_sell | 商店买卖后 | 3 |
| G10 | death | 死亡/战败后 | 2 |
| G11 | idle | 长时间在线/深夜时段 | 2 |

**60 条规则 × 平均 3 条文案 = 180 个触发惊喜**，全部纯数据。

### 2.3 条件 DSL（cond 支持的字段）

`map`（地图id）/ `map_type`（野外/城镇/副本）/ `time`（day/night）/ `weather` / `level`（玩家等级区间）/ `prof`（副业）/ `item`（持有物）/ `flag`（隐藏线）/ `quest`（任务状态）/ `random_chance` —— 全部可选，组合成任意条件。

## 三、数据层（L0）：八大内容域

### 3.1 探索事件扩容（12 → 60）

- 12 个老事件改造为模板 + 每事件 4-6 条文案变体 = **50 条变体**
- 新增 48 个模板实例（firefly/old_well/windmill/hunter_hut/beehive/浮桥/树洞/石碑/货车/夜枭/蛛网/霜花/靴子/蘑菇圈/回音洞穴…）
- **按地图类型挂载**：森林类共享林间事件、水域类共享水畔事件 → 同一事件在不同地图自动换地名文案
- 目标文案：**60 事件 × 平均 5 变体 = 300 条**

### 3.2 彩蛋事件扩容（5 → 30）

- 老 5 个（流星/宝匣/访客/藏宝图/金史莱姆）模板化
- 新增 25 个：区域专属 15（白鹿现身/酒桶幽灵/月光人偶/唱诗班/雾中歌声/烬中凤凰/王都白狐…）+ 全局 10（铁匠鬼魂/时光旅人/宝箱怪/双月同天…）
- 总概率维持 ~0.5%，权重分配
- 目标文案：**30 × 平均 3 = 90 条**

### 3.3 行为彩蛋规则（0 → 60 条）

按 2.2 的 11 个触发器铺开，每条 2-4 条文案。示例：
- 探索 10 连抽未遇怪 → 「运气守恒」补偿 buff
- 连续 3 次采集同一种材料 → 采到"变异的"稀有版
- 背包满时战斗胜利 → 战利品"掉地上滚走了"（笑点）
- 深夜 23 点后探索 → 幽灵概率搭话
- 用火系技能打冰系怪 → 额外融化掉落

### 3.4 交互元素 props（55 → 464）

- **按地图类型模板生成 + 人工审**：每张野外图 3-5 个、城镇 5-8 个
- 城镇模板（12 类）：喷泉/雕像/钟楼/许愿井/花圃/货摊/炉灶/磨坊/船坞/灯塔/马厩/墓碑
- 野外模板（18 类）：篝火/树洞/破屋/沉船/石碑/陷阱/矿车/漂流瓶/老井/树屋/石门/蜂巢/兽穴/鸟巢/岩缝/芦苇丛/枯木/遗迹石柱
- 每类模板 3-5 条文案 → **116 图 × 平均 4 = 464 个实例，1200+ 条交互文案**
- 带 effect 的（许愿/敲钟/点亮灯塔）走 T 模板联动

### 3.5 隐藏怪物（6 → 50）

现有 HIDDEN_MONSTERS 已是纯数据（cond/chance/drops），**加 = 加条目**：
- 按区域补 44 种：南境 8 / 中域 8 / 西境 6 / 北境 6 / 东境 6 / 海域 6 / 地底 4
- 每种专属掉落 + flavor 文案 = **50 怪物 + 50 掉落 + 50 文案**
- cond 扩充：加 `weather`（雨天）/ `weekday` / `world_event` 条件

### 3.6 告示委托（8 → 20）

W1-W8 已设计，补 12 条：各地城镇委托 + 2 条隐藏长链（猫婆婆线/怀表线）
= **20 委托 × 平均 4 条文案 = 80 条**

### 3.7 隐藏 NPC 对话（15 → 60 处）

- 隐藏 NPC 6 个（占卜婆婆/梦游诗人/猫婆婆/雨天商人/神秘剑客/守墓人）每 NPC 8-12 条 = **60 条**
- 已有 NPC 隐藏对话 9 处 → 30 处（按持有物/进度/时段解锁）= **90 条**
- 合计 **150 条对话**

### 3.8 收藏图鉴（109 成就 → 160）

- 成就 +50（探索类：走过全部地图/集齐某区域材料/触发过 N 次彩蛋…）

## 五、扩展指南（未来加内容的 3 种方式）

### 方式 A：加同类型内容（最简单，日常操作）
1. 打开对应数据文件（events_*.py / rules_*.py / props_*.py / hidden_monsters.py）
2. 复制一条现有 dict，改 id/文案/参数
3. 完成。注册层自动加载 + 自动校验（id 唯一、材料存在、模板存在、地图存在）

### 方式 B：加新玩法（一年几次）
1. 在 event_templates.py 注册一个新模板函数（~20 行）
2. 之后所有该玩法的事件都是纯数据
3. 配单测覆盖模板

### 方式 C：加新内容域（大版本）
1. 建新数据文件 + 在注册层挂一行 import + 校验函数
2. 配引擎入口（触发器挂点）

### 自动校验（注册层内置）
启动时检查：模板 id 存在 / 材料、物品、怪物引用存在 / 地图引用存在 / 权重合法 / id 全局唯一 / 文案非空。**有幽灵引用直接报错，不允许带病上线。**

## 七、风险与控制

1. **文案质量**：模板生成 ≠ 机器灌水——每批模板实例人工审校；变体池低于 3 条不发布
2. **平衡性**：T 模板奖励上限 = 同级常规事件 1.5 倍；稀有掉落只服务配方
3. **可发现性**：L2 深藏内容必须有线索链（见闻/对话/告示），禁止无提示纯随机
4. **性能**：规则匹配 = 触发器索引查表，O(该触发器规则数)，可忽略
5. **回归安全**：模板改造期老事件行为不变（先搬家后扩容），全量回归兜底
