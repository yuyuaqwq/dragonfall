## 〇、目标

把 dragonfall 战斗体系从「血条 + 阶段」丰富为「**阶段是题，异常是轴，表现是屏，托管有脑，平衡可测**」：

1. **Boss 阶段状态机升级**：常态→激怒→疲态→狂澜四阶段，每阶段配「数值变化/行为变化/退出条件/反制窗口」四件套；新增「疲态=爆发奖励阶段」（核心件外露）；阶段不回退、跨阶段保留部分进度。
2. **异常体系加固**：在现有毒/灼烧/流血 DOT 上叠加「阈值递增 + 每场上限 + 饱和 + 跨阶段保留 + 独立结算」五律，防无限复读、防无限控 Boss、异常成为独立输出轴。
3. **战斗表现升级**：意图预告（Boss 蓄力/大招提前警示 + 反制提示）、结算卡（终值=素材+下一步）、不刷屏合并。
4. **其他战斗机制吸收**（鱼鱼拍板"其他值得借鉴的战斗机制也可以吸收"）：托管决策序、反伤害海绵三硬规、进度遗产、可体检平衡红线、DDA 轻量动态难度（视性价比取舍）。

## 一、Boss 阶段状态机升级（v138.1）

### 1.1 现状

- `_b_phase`（battle.py ~4085）：阶段演出回合 + `_phase_skip_act` 呼吸点 + 阈值预告
- MONSTER_MODS / INSTANCES 的 `phases` 字段驱动（`_boss_cfg` 读取 opening/triggers/phases/chains）
- 阶段逻辑：血量百分比阈值触发（phases[].min，缺省回退 0.5^n）
- Boss mech 7 种：enrage/summon/heal/shield/phase/stacks/reflect（BOSS_MECHS 注册表）

### 1.2 目标设计

**阶段四件套**：每阶段配 `数值 / 行为 / 退出 / 反制` 四字段（数据驱动，`phases[]` 条目扩展）：

```json
{
  "id": "enrage",
  "name": "激怒",
  "icon": "🔥",
  "atk_mult": 1.25, "def_add": 80, "spd_add": 20,
  "new_skills": ["技能A", "技能B"],
  "turns": 8,
  "exit": {"type": "turns", "value": 8},
  "counter": "读招期，别贪刀",
  "warning": "⚠️【激怒】X 暴怒了！攻击↑ 防御↑——"
}
```

**四阶段模板**（数据层 `data/boss_phases.py` 新表，不写死进引擎）：

| 阶段 | 数值变化 | 行为变化 | 退出条件 | 反制窗口 |
|---|---|---|---|---|
| 常态 | 基准 | 3-4 基础招，前摇 1-2 | HP≤70% 或承伤≥12% | 试招、攒资源 |
| 激怒 | ATK×1.25、DEF+80、SPD+20 | +1~2 新招，前摇压至 1 | 8回合 或 压制倒地 | 读招期，别贪刀 |
| 疲态 | ATK×0.80、DEF−120、核心件易伤+0.40 | 降频（每2回合一动），核心件外露 | 5回合 或 承伤6000 | 爆发期：绝技+破核 |
| 狂澜 | ATK×1.50、DEF+150、霸体 | 每3回合一次全场大招 | 击破；破核→倒地3回合 | 破核是唯一出路 |

**核心原则**：
1. **阶段是内容单位不是血量单位**——强度靠"要解的题"，不靠"要磨的量"
2. **疲态=爆发奖励**：Boss 打累后核心件外露（易伤+0.40），逼玩家在安全窗口集中爆发
3. **阶段不回退**：一旦进入下一阶段，不回退上一阶段；输了有积累
4. **一局最多 4 阶段**，阶段转换前摇挂 ❓ 且不打断已排入行动条的动作（异步公平）

### 1.3 落地改造点

- 新增 `game/data/boss_phases.py`（阶段模板表，纯数据）
- `_boss_cfg` 扩展读取 `phases[]` 的完整四件套字段（现只读 min 阈值）
- `_b_phase` 升级：按阶段模板应用数值变化/行为变化/退出条件/反制窗口
- 阶段演出文本模板化（`🎬` 进场 / `⚠️` 预告 / 退出提示）
- 兼容：旧 phases 条目（只有 min）自动补齐缺省字段，不破坏存量

## 二、异常体系加固（v138.2）

### 2.1 现状

- 毒/灼烧/流血三层 DOT：目标级 `enemy["debuffs"]` 结构（poison/burn/bleed + mark）
- 混合公式：`(atk×系数 + max_hp×百分比) × 层数 × mult × (1-总抗)`，经 `_enemy_mitigate` → `_boss_dmg_filter`
- 适应机制：叠层成功该类型抗性 +4%（cap 20%），2 回合未叠 -4% 消退（DOT_ADAPT_DECAY_STEP）
- 免疫列表 `immune_dots`：命中直接移除
- 控制类：冻结/眩晕/睡眠（eb 字典，回合递减）；`MON_CTRL_EFFECTS` 打断

### 2.2 目标设计：五律

**律一：阈值递增（防无限复读）**

```
每次触发后该类型阈值 ×1.3（封顶 ×3.0 基准）
```

- 目的：同一构筑不能"无限复读同一异常"，逼玩家换花样
- 落地：`debuffs[k].threshold` 字段（首次触发=0，触发后 ×1.3），`_tick_dots` 触发时检查并递增

**律二：每场上限 + 饱和（防 Boss 被锁死）**

```
每个异常每场最多触发 N 次（毒 5 / 灼烧 5 / 流血 5 / 冻结 2 / 眩晕 2 / 睡眠 2）
达上限后进入「饱和」：只结算伤害类（毒/灼烧/流血），不结算控制类（冻结/眩晕/睡眠）
```

- 目的：Boss 永不被无限控死，但伤害类仍可输出
- 落地：`debuffs[k].trigger_count` 字段，触发时 +1；达 `MAX_TRIGGER[k]` 置饱和标记

**律三：跨阶段保留（进度遗产）**

```
阶段转换时：伤害类 DOT 层数保留 50%（向下取整），控制类积蓄保留 50%；新阶段 T+15%
```

- 目的：玩家转阶段前攒的异常条不白费，异步跨天公平性
- 落地：`_b_phase` 转换时调 `_preserve_debuffs`（保留一半层数 + 阈值 +15%）

**律四：异常直伤独立结算（第二条输出轴）**

```
腐蚀/爆燃类真伤不吃 DEF / 护盾（走独立结算），使异常流不依赖"打对部位"
```

- 目的：异常流成为可独立成型的输出维度
- 落地：`DOT_DEFS` 加 `true_dmg: true` 类型（腐蚀），`_tick_dots` 走真伤分支（绕过 _enemy_mitigate 的 def 部分，但仍走免疫检查）

**律五：饱和阈值收敛（防极端值失控）**

```
所有异常"每场上限"累计触发后，异常易伤乘区（如有）逐次递减 ×0.8
```

- 目的：防极端构筑把 Boss 异常易伤叠爆（对应我们 v133 峰值红线精神）
- 落地：`debuffs[k].saturate_mult` 字段，饱和后递减

### 2.3 落地改造点

- `game/core/constants.py`：新增 `DOT_THRESHOLD_MULT=1.3` / `DOT_THRESHOLD_CAP=3.0` / `DOT_MAX_TRIGGER={poison:5,burn:5,bleed:5,freeze:2,stun:2,sleep:2}` / `DOT_PRESERVE_PCT=0.5` / `DOT_SATURATE_MULT=0.8`
- `game/battle.py _tick_dots`：加阈值递增、每场上限+饱和、跨阶段保留调用点、真伤分支
- `game/data/battle_config.py`：DOT_DEFS 加 `true_dmg` 字段支持（腐蚀类）
- 控制类：`MAX_TRIGGER` 在 eb 上记录触发次数（冻结/眩晕/睡眠）
- 兼容：旧 debuffs 无 threshold/trigger_count 字段 → 默认 0，不崩

## 四、其他战斗机制吸收（v138.4）

### 4.1 托管决策序（超时自动防御 → 预案执行）【v138 决策：文档化 + 最小增强，代码后置】

- 现状：副本超时 60s 自动防御（`_instance_auto_defend_player`，instance.py ~2598）——置 p_defending + 手动结算 CTB ct
  - **2026-08-30 审计注**：副本超时自动防御属**命令层调度**（instance.py `_instance_auto_defend_player`）；battle.py 的 `_inst_auto_defend` 是零调用死代码（收编方案已废弃，随修复删除）。副本战斗引擎现状 = **瞬态 Battle 结算器（player_turn）+ 命令层 CTB 调度**（instance.py `_instance_*` 前缀方法）。
- 升级方向（设计定稿）：超时代打按决策序：血线<40% 走保底位（防御/道具）→ 资源到阈值就释放（不屯）→ 打最软处（标记>已破坏>防御最低）
- **v138 落地决策（2026-08-29 主 agent 收尾确认）**：
  - 副本 CTB 是核心玩法，`_instance_auto_defend_player` 的手动 ct 结算与 `player_turn` 内部 ct 结算会重复
  - 直接调用 player_turn 完成超时自动行动 → 需重构整个超时流程，风险高，收益不确定（超时玩家本就该被"惩罚"为防御）
  - **本期**：保持防御语义（CTB 零风险），新增 `_next_step_hint` 结算卡养成指引 + 反制窗口提示已覆盖"引导玩家主动操作"的目标
  - **后续版本**：若做，建议给玩家加"托管预案"标记位（data 驱动，`st["auto_plan"]`），超时时按预案选动作，需重构 `_instance_auto_defend_player` 为 async + player_turn 流程
- 红线：托管/在线 TTK 比 ≤1.35（写入 32 章观测项）

### 4.2 反伤害海绵三硬规（设计规范 + 校准脚本）

```
① 敌人 HP 版本增长 ≤ 玩家攻击成长的 60%
② TTK>12 的战斗，窗口期（破坏倒地/压制/异常爆发）贡献 ≥ 35% 总输出
③ 每 3-5 回合必出新变化（新意图/阶段转换/部位暴露/增援）
```

- 落地：写入 32 章数值设计文档 + `scripts/numeric_calibration.py` 加窗口占比校验（输出报告不强制失败，作为设计观测）

### 4.3 进度遗产

- 现状：27 章明确写 phase 清除全部减益
- 升级：阶段转换保留 50% 减益/积蓄（对齐异常律三）；文档同步修订
- 落地：`_b_phase` 转换时调用 `_preserve_debuffs`
