## 〇、一句话概括这次改什么

> **把 12 条线从"12 个攒满就放的资源条"，改成 12 个不同的决策。**  
> 砍掉"隐藏职业"这层壳，把它的机制精华拆进六职业的第二条线；  
> 把"攻线/守线"这个已经不描述任何东西的命名，换成"你靠什么赢"；  
> 把决策从战内（玩家够不着）前移到战前（QQ bot 唯一能操作的地方）。

## 一、诊断：同质化的根因

### 1.1 效果指纹 ≠ 玩法指纹

`class_design_audit_20260829.md` 的结论是"✅ 12 职业无效果同质化，每个职业都有专属效果指纹"。这个结论没错，但它统计的是**效果类型的数量**（战士 6 破防 / 刺客 12 毒 / 法师 8 AOE / 游侠 9 标记）——这只证明**皮肤不同**，不证明**玩法不同**。

把皮肤扒掉，v142 的 12 条线骨架是同一个：

```
打中 / 挨打 → 攒一条 0~N 的资源 → 攒满 → 放一个 300%~500% 的终结技 → 归零重来
```

跑这条循环的线：**战士(怒气)、刺客(连击点)、星语者(猎印)、暮影(影步)、淬势者(禅意)、拳师(气)、龙裔(龙力)** —— 12 条里 7 条。区别只有"资源叫什么"和"攒多快"。

### 1.2 这个循环还有个纪律问题：攒满就放 = 最优解

资源上限存在 → 满溢即浪费 → 最优策略永远是"一到阈值就放"。  
于&#x662F;**"资源管理"根本不存在，只剩"资源计时"**。玩家不看战况，只看数字到没到。

v142 里唯一真正的资源管理是**游侠的精力**（100 上限 / 自然回 30 / 三档预算）——每回合永远有箭、但永远要取舍花在哪。结果它恰恰是数值崩得最惨的那条线（狩猎终章 desc 480% vs 实装 power 1.202，差 4 倍）。

**这不是巧合**：预算制是最难用"攒满就放"记账法表达的，所以它第一个崩。

### 1.3 三条硬伤

| #      | 问题                 | 证据                                                                                   | 后果                                                         |
| ------ | ------------------ | ------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| **H1** | **隐藏线机制撞车**        | 星语者(猎印/标记) ↔ 游侠攻线林语者(标记/毒)；淬势者(破绽推条) ↔ 拳师攻线格斗士(破绽)；暮影(影舞态/潜行) ↔ 刺客攻线影舞者              | 隐藏线不是"变奏"，是同源机制换皮 + 数值 +30%                                |
| **H2** | **`power` 字段已失真**  | 表头写"1.0 = 100% 倍率"，实装 `怒斩 power 1.166 / desc 238%`、`无畏冲击 power 0.724 / desc 满怒 220%` | 它既不是基础倍率也不是最终倍率，是把 CD、多段、条件增伤全搅进去的等效量。**设计者自己已读不出一个技能打多少** |
| **H3** | **"攻线/守线"不描述任何东西** | 游侠守线=速度增伤、法师守线=奥术叠层、牧师攻线=诗人增益、龙裔 role=坦克但无嘲讽                                         | 玩家按字面理解去选，选完发现守线一点都不肉                                      |

### 1.4 一条被低估的资产：战前预案 DSL

v139 已经在 6 个职业上做了"战前档位"：

- 刺客 `finisher_threshold`：快刀 / 满刃 / 残血 / 满段（4 档）
- 暮影 `ambush_plan`：满步即入 / 等倒地窗口 / 伏击蓄势 / 残血保命（4 档）
- 淬势者 `dual_form.preplan`：满意即倾 / 等倒地窗口 / 攒到 5 档才放 / 残血搏命（4 档）
- 龙裔 `DRAGON_FORM.enter_requirement`：满力 10 / 储备 8 / 窗口 / 血线
- 战士 `dual_form`：满怒 10 / 7 怒 / 窗口 / 血线
- 游侠 `VENT_CFG.max_delay`：常规硬吃 / 快排泄压 / 深排等窗口

**这是全项目唯一让 QQ bot 玩家真正做决策的地方** —— 战斗自动结算，玩家够不着战内；但战前配一套预案，托管就会按预案执行。

v150 要做的：把它从"6 个职业的特例"升格为 **12 条线通用件**，每条线 1~3 个预案槽。

## 二、新结构：6 职业 × 2 战术线

### 2.1 结构对比

```
v142：  6 基础职业 × 2 分支 × 3 档  +  6 隐藏职业 × 1 分支 × 3 档   = 18 个分支名，12 个 class id
        └─ 隐藏线 = 独立职业 + 种族锁 + 40 级任务链 + 只有 20% 内容量

v150：  6 职业 × 2 战术线 × 3 档                                    = 12 个分支名，6 个 class id
        └─ 隐藏线机制拆解并入；种族锁取消；30 级选线，60/90 沿线深化
```

**引擎收益**：

- `core_resource_def(cls)` 不用再处理 12 个 class 的资源解析
- `BRANCH_RESOURCE_OVERRIDE` 只保留 3 条（法师双线 / 牧师 A 线），其余回落单资源
- 种族锁（`src_race`）相关的转职拦截逻辑整段删除
- 隐藏职业任务链（6 条）转为"线的背景叙事"，不再是解锁门禁

### 2.2 命名规则：从"攻/守"到"你靠什么赢"

分支的**展示名**改为"战术线"，命名依据是**这条线赢下战斗的方式**，不再按输出/承伤二分。

> ⚠️ **落地约束**：`classes.py` 的 `evolve_branches` 分支 key 与 `skills.py BRANCH_SKILLS` 键强耦合（技能授予/路由按 key 匹配），**分支 key 一律不改**。  
> 新名走两条路：① `evolve` 展示列表直接写新名 ② `aliases` 补新名 → 旧 key（沿用 v130.2 淬势者"苦修士→淬势者"的既有先例，零引擎改动）。

### 2.3 隐藏六职业的归宿：拆解，不是删除

隐藏线的**机制**是好东西，**职业壳**才是问题。六条线的拆解映射：

| 隐藏职业     | 归宿                | 带走什么                                       | 丢掉什么                            |
| -------- | ----------------- | ------------------------------------------ | ------------------------------- |
| 🐉 龙裔誓约  | → **战士·血怒线**      | 真伤爆发轴、龙焰双形态、灼烧三件套、内燃（火免转真伤）                | "坦克"这个名不副实的 role、10 点龙力资源、龙裔种族锁 |
| ⏳ 时咒法师   | → **法师·时律线**（整条搬） | 时间凝滞、积沙银行、减速→眩晕→停滞控制链、时停领域、时间侵蚀自动出伤        | 5 点时之沙资源（并入元素充能条）、人类种族锁         |
| 🔮 星语者   | → **游侠·疾风线**      | 星轨锁定（点名权，无视站位直击）、蓄力狙击 reach 3、满值强制排气       | 猎印资源、银月精灵种族锁、与林语者撞车的标记体系        |
| 💀 暗影神谕  | → **牧师·幽祷线**      | 骷髅海、死亡契约免死、骨噬诅咒挂敌身（不可驱散）、灵魂标记、死歌三调         | 悼咏资源（并入信仰）、兽人种族锁、满溢转盾           |
| 🗡️ 暮影行者 | → **刺客·影舞线**      | 影舞态（满步自动进 / 锁死累积 / 3 回合 / CD-1）、伏击四预案、潜行乘区 | 影步资源、半身人种族锁、与基础刺客重复的"暗影之舞"被动    |
| 🥊 淬势者   | → **拳师·破绽线**      | 撼岳之势（挂敌身软控，免疫怪唯一软解）、慢热持有加伤、四档倾泻结构          | 禅意资源、矮人种族锁                      |

**净效果**：隐藏线的每一个"签名机制"都活下来了，但每条都从"一个独立职业的全部"降级为"一条线的增量"。撞车问题解决（星语者的标记让位给林语者，淬势者的破绽让位给格斗士），因为**它们现在坐在同一条线的不同侧**。

## 三、区分度的可验证标准：决策问句

### 3.1 判据

> **两条线同质 ⟺ 它们的核心决策问句相同。**

这是可验证的：把每条线的核心问句写出来，如果有两句是同一句，那两条线就是换皮。v142 用这把尺子量，7 条线的问句都是同一句——**"攒满了没？"**

### 3.2 十二条线、十二个问句

| 线     | 核心决策问句               | 玩家真正在权衡什么                                            |
| ----- | -------------------- | ---------------------------------------------------- |
| 战士·血怒 | **"你敢剩多少血？"**        | 血线越低 → 受击回怒越快（1+⌊缺失HP%×4⌋，封顶 5）→ 但也越容易死              |
| 战士·铁誓 | **"你敢接多少打？"**        | 开嘲讽 = 吃全部伤害，但怒气涨最快、反击触发最多                            |
| 法师·元素 | **"铺几层再引爆？"**        | 每层印记 0-3；早引爆频率高但倍率低，攒满引爆慢但一次清空                       |
| 法师·时律 | **"敢站桩几回合？"**        | 凝滞态每回合 +2 沙 + 自动侵蚀 60% 伤害，但受击 +20%、崩架 30%、只维持 3 回合   |
| 游侠·林语 | **"标记挂给谁？"**         | 集火一个（标记叠满 +30% 特攻）vs 铺毒多目标（毒爆清算）                     |
| 游侠·疾风 | **"蓄几阶？点谁？"**        | 电荷 0.7/1.3/1.9 边攒边打；满阶强制释放；狙击 reach 3 可点后排           |
| 牧师·圣咏 | **"共鸣花在增益还是伤害？"**    | 短燃料共鸣 0-10：花在团队增益（全队 100%/自身 55%）还是破晓长歌（EQ≈4.8）      |
| 牧师·幽祷 | **"铺场还是攒大？"**        | 悼咏花在召唤骷髅（挡刀 + 灵魂标记）还是攒到 10 放安魂曲（300% 全体 + 半额回血）      |
| 刺客·影舞 | **"几点终结？"**          | 快刀 cp≥3（高频低峰）vs 满刃 cp=5 vs 残血 vs 满段链值≥8              |
| 刺客·毒刃 | **"几层引爆？"**          | 毒层伺服到 5 停投喂；早引爆频率高，攒满引爆一波流但怕被驱散/怪死                   |
| 拳师·破绽 | **"专打一个还是换目标重开？"**   | 破绽阈值每次触发 ×1.35 递增（封顶 ×2.5）；换目标 = 阈值重置但进度清零           |
| 拳师·磐核 | **"3 核早放还是 5 核攒满？"** | 磐岩释能 M = 1.0 + 0.7n（线性刻意）：3 核 3.10 高频 vs 5 核 4.50 峰值 |

**十二个问句，没有一句重复。**

### 3.3 六种资源经济原型

问句之所以不同，是因为底层的**资源经济模型**不同。这是 v150 的核心分类法——**资源叫什么不重要，钱怎么来、怎么花、什么时候必须花才重要**。

| 原型         | 定义                       | 收入方式      | 决策点           | v150 用在            |
| ---------- | ------------------------ | --------- | ------------- | ------------------ |
| **A. 蓄池型** | 攒满即放                     | 命中/受击     | ❌ 无（攒满就放是最优解） | **全部淘汰**（v142 的病根） |
| **B. 预算型** | 每回合固定收入，花光才不浪费           | 自然回 / 每回合 | 花多少、花在哪       | 游侠（双线）             |
| **C. 持有型** | 资源留在手里就有收益，花了就没          | 出招/连击     | 忍住不放 vs 见好就收  | 拳师（双线）             |
| **D. 窗口型** | 攒满自动进形态 / 强制排气，形态内锁死累积   | 命中/受击     | 形态前铺垫什么       | 战士血怒、刺客影舞、游侠疾风     |
| **E. 转化型** | 用别的东西换资源（血换怒、治疗换信仰、挨打换气） | 代价交换      | 拿什么去换、换多少     | 战士（双线）、牧师（双线）、拳师磐核 |
| **F. 挂账型** | 资源挂在敌人身上，不占自己资源位         | 命中注入      | 专打一个 vs 铺开    | 拳师破绽、游侠林语、牧师幽祷     |

**自检**：每条线至少命中 2 个原型，且**没有任何两条线的原型组合完全相同**。

- 唯一"无团队贡献"的三条线 = 战士血怒 / 刺客影舞 / 法师元素 → 这正是它们的**定位代价**（纯 selfish carry），是有意设计不是遗漏
- 唯一"无生存手段"的一条线 = 拳师破绽 → 前排 + 无减伤 + 无回复，这是全游最高风险线，需要数值上用高血防成长补（HP 18/级已是全职业第二）
- 控制能力分布：时律（减速×4 眩晕×3）> 破绽（跳过回合/震慑）> 血怒（无）→ 梯次清晰

## 五、数值记账法重建（解决 H2）

### 5.1 三层分离

v142 的 `power` 字段把四样东西搅在一起，导致 desc 和数值系统性脱节。**根因是它在试图用一个数字表达"这个技能最终打多少"——而这是算出来的，不是写出来的。**

v150 拆成三层：

```
base        基础倍率        —— 裸技能倍率，1.0 = 100% atk/matk。手写，唯一真值源。
scaling     缩放项（列表）  —— 每一项独立成行，可枚举：
                              · 资源层：rage×0.12 / zen×0.12 / chi×0.03 / combo×0.05 (cap 0.40)
                              · 形态：fury ×1.20 / focus ×1.40 / shadow_dance ×1.25
                              · 条件：enemy_hp_low(<40%) ×1.40 / self_hp_low(<50%) ×1.25
                              · 连动：mark ×1.20 / curse ×1.20 / reaction ×1.30
                              · 多段：segments 3
eq          等效倍率        —— 【派生值】，由脚本从 base + scaling 算出。
                              禁止手写、禁止进数据表、禁止出现在 skills.py。
```

**配套铁律**：

1. `desc` 文案由 `base + scaling` **生成**，不手写百分比
2. 文档里的"EQ"列由 `tools/calc_eq.py` 生成，不从数据表抄
3. CI 门禁：`desc` 与生成值不一致 → 测试失败

这样"死神之箭 desc 450% vs power 2.693"这类脱节**从根上不可能再发生**。

### 5.2 天花板与红线

| 项           | v142 现状            | v150 目标                      |
| ----------- | ------------------ | ---------------------------- |
| T1 单发 eq 上限 | ~2.9（终结·处刑 4.0 已超） | **2.5**                      |
| T2 单发 eq 上限 | ~3.6               | **3.5**                      |
| T3 单发 eq 上限 | ~6.4（龙脉终曲）         | **4.5**                      |
| 全场单发红线      | 同级怪血 42%（v133）     | 沿用 **42%**                   |
| 真伤 / 破防 折算  | 与常规同权              | **×0.8 计入 eq**（绕过减伤，等效收益已更高） |
| AOE 折算      | 与单体同权              | 目标数 ≥3 时 **×0.6 计入 eq**      |

**膨胀压缩的副产品**：T3 从 500% 降到 450% 后，T1/T2 技能不会在三转后立刻全废，"技能栏 6 格"的取舍才真正成立。

> ⚠️ 这一章是**第二阶段**，需要 `run_numeric_tests.py` 全量重跑 + 峰值红线复核，不要在框架确认前动数值。

### 5.3 工具化

`tools/calc_eq.py`：输入 `skills.py`，输出全技能 eq 表 + desc 一致性报告。  
`tests/test_skill_desc_sync.py`：CI 门禁。
