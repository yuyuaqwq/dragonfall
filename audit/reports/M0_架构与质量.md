## 5. 亮点清单（≥3 条）

1. **白名单=注入约束**：所有动态列名 SQL（`update_player`→`PLAYER_FIELDS`、`bump_stats`→`STAT_FIELDS`、`add_prof_exp`→`PROF_FIELDS`）均以模块级静态白名单先行校验后拼接，杜绝拼接用户键——这是全库最扎实的安全基线，M2/M3 双证（store/players.py:244-246、stats.py:26-29、professions.py:77）。`executescript`/表名只在 init_db 常量 SQL。
2. **交易/领取类原子写到位**：`sell_item_atomic`/`market_buy_atomic`/`market_stall_sell_atomic`/`market_exchange_atomic`/`home_storage_deposit/take_atomic`/`props_use_claim_atomic` 全部用 `atomic()`（`BEGIN IMMEDIATE` 单事务）做读-判-写，附防"重复发钱/重领"注释（store/social.py:259-331、world.py:373-422、props_use.py:46）——并发写正确性的模范范式。
3. **装配顺序显式纪律 + 单一数据源收口**：`data/_assembly.py` 头部明写"先派生表再 build_index"，`data/__init__.py:94` 末尾 `from . import _assembly` 统一定时装载，`MAP_BY_ID` 由 MAPS 单一数据源重建（_assembly.py:114-117），把历史多源失步问题收口——好的装配设计。
4. **RLock 防死锁 + 延迟导入隔离循环**：`connection._lock` 由 Lock 升级 RLock（connection.py:19-21），规避 `get_player` 惰性升级内再调 store 的死锁；12+ core 模块统一"函数内 `from .. import db`"+踩坑注释，把循环风险逐点标明。
5. **敏感信息收敛 + 自愈式 schema 演进**：webhook `secret`/`url` 从内联明文改为环境变量 + HMAC-SHA256 签名（misc.py:366-404）；`_ensure_legacy_columns` 用 PRAGMA table_info 惰性 ALTER 对存量库补列（connection.py:281-378），并有多道脏数据防线（`_jload` 防 'null' 串、读档 clamp hp/mp）。
