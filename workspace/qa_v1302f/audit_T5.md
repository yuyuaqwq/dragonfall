## 一、各挂点现状与边界结论

### 1. 亡灵祭仪（battle.py:4258-4268，回合初悼咏 +1/亡灵，最多 2 只）
- **挂钩方式**：仅按职业核心资源 key == `canticle`（cls_hymn 暗影神谕）判定，不看任何被动/技能（skills.py 全库 0 处「亡灵祭仪」）→ 职业天赋级挂点，双分支（暗影祭司/亡魂引渡者）均生效。
- **计数口径**：`_undead_count()`（battle.py:2487-2497）= 玩家召唤（tid=skeleton 或名含「骷髅」且 hp>0）＋ 敌方名含 亡灵/骷髅/僵尸/幽灵（hp>0）。
- **骷髅阵亡计数**：✔ 正确。死亡召唤物 hp=0 即被过滤（实测 hp=0 骷髅不计）；清理由 `_summons_act` 完成（4609-4636），挡刀致死（`_summon_bodyguard`）也只留 hp=0 残体，计数不受影响。
- **上限 2 只**：✔ `min(_ud_n, 2)`；3 骷髅实测 → +2（官方测试 276 行同断言）。
- **与召唤骷髅 CD/上限 3 交互**：✔ 无冲突。召唤上限 3（summons.py skeleton limit=3）为「达到上限拒绝再召」（`_summon_entity` 4592-4595，无替换机制）；祭仪只吃计数不干涉召唤；骷髅 CD3/耗 2 悼咏与回合初收益各自独立。
- **敌方亡灵计入**：⚠️ 打 旧王陵（骷髅兵/僵尸）等亡灵怪时每回合开局白嫖 +1~2 悼咏（与暗夜圣典 2 件 undead_on_field 同一口径——v130.2f 已把两者统一到 `_undead_count`）。属有意设计（docstring 明示与成就 亡灵使者 同源），但收益面比「自家骷髅」大得多，需策划确认（P2 ⚠️）。
- **与暗夜圣典 2 件叠加**：回合初 套装+1 与 祭仪+≤2 可同时结算，上限 +3/回合。
- **满悼咏溢出**：`_res_gain_class` 满 10 转 5 盾/点，但 `_ud_now > _ud_before` 日志闸门在满值时吞掉「亡灵祭仪」日志（实测：10→10+盾 5，无祭仪文案）→ 玩家只见护盾凭空出现（P3 文案）。

### 2. 反击回气 +2（battle.py:4878-4897，以守为攻/反击之王 反击命中后 气+2）
- **挂钩方式**：骑在 `counter_attack` proc（以守为攻 lv48 20%、反击之王 lv62 30%，均拳师守线）roll 成功后；回气本身只按「职业核心资源 key==chi」放行 → 无越权面（只有拳师有 chi；其他 counter_attack 源不存在）。
- **【任务必查】反击 miss 是否也回气**：当前**反击路径不存在 miss**——主攻击/技能路径都走 `_monster_dodge_check`（battle.py:2189-2190、3309，怪物闪避最高 30%），但反击路径（4878-4897）直接 `_damage_enemy`，无闪避判定（v107 遗留，非本次新增）。
  - 因此「命中才回」实际退化为「触发即回」；真正可复现的缺口是 **0 伤害反击**：反击伤害被压到 1（高防场景实测 calc_damage(216, 99999)=1，calc_damage(5000, 200000)=121）且 Boss 有护盾时，`_boss_dmg_filter` 50% 削减 → int(1×0.5)=0（实测 `_boss_dmg_filter(1, shield)=0`）→ `_damage_enemy(0)` 打 0，**回气 +2 照发**（4892-4896 无伤害/命中校验）。PVP 无此边缘（pvp 直接 return dmg，3598-3599）。
- **与格挡/反震叠加**：格挡（4800-4812）不阻断反击 roll；反震（reflect 被动）/荆棘反伤/格挡反击（block_counter）各自独立 roll，可与反击回气同回合多通道并存——设计确定项（v109 已定「逐个独立 roll，命中即停」），回气只挂在 counter_attack 上，无双计。
- **PVP**：同一受击路径生效 ✔；PVP 无 boss 护盾 → 0 伤害边缘不存在。

### 3. 致命预谋首次终结返还 1CP（_assassin_finisher_refund battle.py:2376-2390；扣费点 1896-1898 consume_all / 1913-1915 res_cost）
- **返还时机**：两分支均挂在「扣费成功之后、技能结算之前」。consume_all cp：清零后返还（实测 5→0→1）；res_cost cp：扣后再 +1（官方测试 5-3+1=3）。
- **防重复**：
  - `_assassin_refund_used` 标记：to_state（battle.py:441-442）/ from_state（496）均序列化 ✔（实测：还原战斗后首次终结仍返还、第二次不再返还，flag 还原正确）。
  - 蓄力技二次触发：释放路径 `_releasing=True` 跳过两扣费点（1849/1901）→ 不会二次返还 ✔；且当前数据中无 cp 蓄力技（skills.py 扫描 mu_shi/ci_ke 均无 charge），风险面为空。
  - 战斗中断/重开：新战斗全新标记，无污染。
- **边界**：
  - 标记在「真实增量检查」之前置位（2385）→ cp 已满时返还落空但标记照吞（P3，纯资源上限边缘）。
  - 返还先于技能结算；当前数据下终结技无「结算后失败」路径（治疗目标无效不适用攻击技、MP 预检在先、暗杀/处刑等 cond 均为增伤非拦截）→ 不存在「返还被废施」实际路径（P3 防御备注）。
  - **双收益并存**：战斗开始 +1 cp（v110.3 原效果，battle.py:863-865）＋ 首次终结返还 +1 cp 同时有效（官方测试 316-317 与 320-322 双断言）——设计意图明确（保底节奏），但 desc 仍只有「战斗开始获得1连击点」，未收录返还承诺（P2 文案）。

### 4. 歌者伴奏 20% 回声（battle.py:1950-1956，配合 _is_bard_skill 1208-1215 / _echo_add 1194-1206 / _res_gain echo 582-584）
- **判定范围**：`_is_bard_skill` = ① 职业必须是 cls_mu_shi；② 当前分支 ∈ BARD_BRANCHES（吟游诗人 t1p1 / 灵魂歌者 t2p1 / 黎明颂者 t3p1）；③ 技能 owner 分支 ∈ BARD_BRANCHES。
  - 实测：吟游诗人-战歌 True；灵魂歌者-鼓舞 True（echo 2 = res_gain 1 + 伴奏 1）；大主教(t2p2)-神圣恩典 False；神谕者/圣光先知 False；基础技能（大治愈术等）False。
  - **非歌者分支误触发**：无。伴奏被动本身只在 灵魂歌者 技能树（lv65），引擎又以分支+cls_mu_shi 双闸，正常游戏内无越权路径。
- **回声 max3**：✔ `_res_gain("echo")→_echo_add`，cap=ECHO_CFG.max_layers=3（实测满层不再叠）。
- **边界缺口**：
  - `_is_bard_skill` 的 `info is None → return True`（1212-1213）：若未来调用方 info 缺失会把任意技能当歌类技。当前 `_do_player_skill` 在 1840-1843 已拦 None，不可达（P3 防御）。
  - 20% 硬编码（1955）vs 数据 passive.chance=0.2：数值一致但改数据不回流（P3 数据驱动一致性）。
  - 蓄力技：当前无歌类蓄力技；若未来加，回声在「释放」路径（_player_charge_release→_do_player_skill，1399-1406）可达，施放路径会提前 return（1948）——实现语义为「释放时结算」，需与 desc 口径对齐（备注）。
  - BARD_BRANCHES 含三阶歌者分支，但 _is_bard_skill/_echo_add 硬前置 cls_mu_shi——中立线 cls_bard（吟游诗人独立线）永不触发（现状无影响，未来接歌者资源需重构）（P3）。
