# audit_T1.md — 意见#2 批量购买（『购买 <物品>*<数量>』，标 done 待核实）

## 结论
- **done 标记部分成立**：批量购买的**空格格式**『购买 <名称> <数量>』确实早已实现（v95.25 #127，economy.py buy 处理器）——但**意见原话要的星号格式『购买 <物品>*<数量>』未实现**：旧解析只按空格切分，`治疗药水*5` 会被整体当成商品名搜索 → 「商店里没有『治疗药水*5』」。
- 另核实到**数量校验缺口**：0/负数被 `max(1, ...)` 静默钳成 1（买 1 个）、超 buy_qty_max 被静默钳到上限（用户感知为「买少了/买错了」）；上标数字（²/³，`isdigit()`=True）会在 `int()` 抛 ValueError 崩溃。
- **已实现闭环**：星号格式 + 显式校验（间隔符 `*` 与空格双支持），31/31 验证通过，既有回归 27/27、37/37 全绿。

### 2. 缺口（意见成立部分）
- **星号格式 0 支持**：grep `*` 数量格式在 buy 处理器/测试中 0 命中；`购买 治疗药水*5` 旧行为 = 名称整体匹配失败 → 「商店里没有『治疗药水*5』」（economy.py:4563 兜底）。
- **静默钳制**：旧 `qty = max(1, min(int(...), _ec["buy_qty_max"]))`（economy.py:4283 改动前）——0/负被钳成 1，超 999 被钳成 999，无任何提示。
- **上标崩溃隐患**：`_parts[-1].isdigit()` 对 `²`/`³` 返回 True 而 `int('²')` 抛 ValueError → 单条消息即可崩 buy 处理器。
