# R6 CTB 时刻制审查卡（机制/数值层）

## 任务
审查 dragonfall **所有战斗相关机制**里"回合"概念的分布。鱼鱼问：所有技能、buff、道具效果等等都得重构成时刻？整个战斗都不能有回合概念？

## 背景
R5 负责看 battle.py 核心时序；**你负责看机制/数值/数据层**：buff、异常、技能 CD、道具、被动、姿态、架势、dot/hot 的时间单位。

## 具体要查
1. **buff/异常状态**：
   - 搜 `duration`、`持续`、`回合`、`round`、`turn`、`tick` 在以下文件的分布：
     - `game/data/skills.py`（技能 buff 定义）
     - `game/data/battle_config.py`
     - `game/core/` 下 buff 相关模块
     - `game/engine.py`（buff 应用）
   - buff 的 duration 单位是什么？（回合数？秒？时刻数？）
2. **技能 CD/冷却**：
   - 技能定义里的 `cd`/`cooldown` 字段单位？
   - 战斗中 CD 怎么减？每回合减 1？还是按 CT/时刻？
   - 搜 `cd`、`cooldown`、`冷却` 在 skills.py/engine.py/battle.py
3. **战斗道具**：
   - `game/data/items.py` 战斗道具的效果持续时间单位？
   - 消耗品 buff 是回合还是时刻？
4. **dot/hot/持续性效果**：
   - 中毒/燃烧/流血等 dot 是几回合跳一次？字段名？
   - hot（持续治疗）同理
5. **被动/触发类**：
   - "每回合触发"类被动（如有）→ 回合单位
   - "行动后触发"类 → 时刻单位
6. **改造评估**：
   - 汇总所有用"回合"作为时间单位的机制（文件:行号 + 字段名 + 当前单位）
   - 这些机制的消费者（引擎哪些函数读这些字段）
   - 若改时刻制，数据层/引擎层各要动多少（粗估，不用精确）

## 必读文件
- `game/data/skills.py`（技能/buff 定义）
- `game/data/items.py`（道具）
- `game/data/battle_config.py`
- `game/engine.py`（buff 应用/结算）
- `game/battle.py`（战斗结算）
- `game/core/battle_modes.py`、`game/core/battle_bars.py`、`game/core/battle_conds.py`（战斗机制模块）

## 输出
按 FRAMEWORK.md 格式，重点是**完整清单**：所有回合单位机制 + 字段 + 文件:行号 + 引擎消费点。
