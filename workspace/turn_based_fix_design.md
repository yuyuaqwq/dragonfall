# 回合制效果 → 时刻制改造方案（v151 配套，待审计确认后细化）

## 问题（鱼鱼原话）
"旧的一些效果是基于回合的问题，比如防御药水防御3回合，但是如果全是自己的回合，这个防御有啥意义，是不是应该改成基于时刻？"

## 现状（主 agent 已确认）
- CTB 速度条：`BASE_DELAY/spd` 决定行动频率，玩家快则每轮行动 2 次、敌人才 1 次
- `self.round += 1` = 玩家每行动一次 +1（battle.py:1634）
- `_end_round`（battle.py:5260）每轮结束统一递减 p_buffs/e_buffs
- 一轮 = 玩家行动 + 敌方行动（player_turn → _enemy_phase）
- 防御药水 buff_def → p_buffs["def_up"] = 3（items.py:2053），3 回合递减
- 已有豁免：stun/freeze（行动级控制）、fire_mark 等（印记层数）、next_atk_up/stealth（一次性消费）、reduce_all/shield（特殊计时）

## 核心问题
防御/减伤类 buff 按"轮数"递减，但防的是"敌方出手"。
- 玩家速度极快（每轮行动 2 次敌 1 次）→ 3 回合里敌方只出手 1-2 次，防御价值大打折扣
- 玩家速度慢（每轮行动 1 次敌 2 次）→ 3 回合覆盖 4-5 次敌方出手，防御过强
- 攻击类 buff 同理反向失真

## 改造方案（待拍板）

### 方案 A：按"敌方出手次数"计防御类 buff（推荐）
- 防御/减伤类 buff（def_up/mdef_up/reduce_all/shield 等）改为记录"剩余 N 次敌方出手"
- 在 `_enemy_phase` 每次敌方行动时递减
- 防御药水"3 回合防御+45%" = "挡 3 次敌方出手"，语义清晰、不受速度差影响

### 方案 B：按"行动点（时刻）"计所有 buff
- buff 记录"剩余 N 个行动点"，玩家行动时 -1（对攻击类），敌方行动时 -1（对防御类）
- 更精细但改动面大（要区分 buff 类型决定谁扣）

### 方案 C：保持回合制，只改文案和数值
- 承认"回合"= 轮数，把防御药水改成更高防御/更短回合
- 最简单但没解决"全是自己回合时防御无意义"的根本问题

## 我的推荐
**方案 A + 有限方案 B 混合**：
1. 防御/减伤/护盾类（防敌方）→ 按敌方出手次数计（方案 A）
2. 攻击/暴击/速度类（增益自己）→ 保持按轮数（玩家行动频率高时收益自然高，符合直觉）
3. DOT（灼烧/毒/流血）→ 保持按轮数（每回合掉血本来就是轮数语义）
4. 控制（眩晕/冰冻）→ 已是行动级，不动

## 落地点（引擎层，主 agent 亲写）
1. battle.py `_enemy_phase`：敌方每次行动前，对 p_buffs 里标记为"防御型"的 key 递减
2. 数据层：把防御型 buff 的 key 标记（如 `p_defense_buff_keys = {"def_up", "def_up_strong", "mdef_up", ...}`）
3. 药水/技能/套装 desc 文案同步改（"挡 N 次敌方出手"）

## 需要审计确认的
- 哪些 buff key 是"防御型"（要改按敌方出手）
- 哪些是"攻击型"（保持按轮数）
- DOT/控制/印记的豁免清单（已有注释确认）
