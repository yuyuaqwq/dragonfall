# 任务卡 F03 意见#17 多目标战斗任务击杀计数（先读 FRAMEWORK.md 公共框架）

## 背景
玩家意见#17（回滚为 new）：『如果遇到多个目标的怪物，只有后击杀的怪物才会计算进任务里』——真 bug，鱼鱼点名修。
根因（审计确认）：victory 结算只传阵列首位主怪（combat.py:821-826 `_mon = b._origin_enemy or b.enemy`，battle.py:234 `_origin_enemy = enemies[0]`），`_update_quests`（combat.py:1920）每场只调一次、只对单个 monster 计数 → 多怪战（40% 双只/精英带爪牙/Boss 带小怪）副怪击杀全部丢失。

- game/battle.py：`__init__`（enemies 结构、to_state 序列化）、`_remove_unit`（4736-4758，敌方单位死亡统一移除入口）、234 行 `_origin_enemy`
- game/commands/combat.py：816-827（胜利分支）、1918-1925（_update_quests 调用点）、2050-2135（主线/每日/支线计数函数体）

## 任务（精确改动点）
## 方案
1. battle.py：`__init__` 新增 `self.killed_enemies = []`（敌方死亡单位的原始 dict 快照列表）。
2. `_remove_unit` 中 `side == "enemy"` 分支：把 `unit`（或 compact 返回的 removed 列表中敌方单位）的 **dict 副本**（`dict(unit)`）append 进 `self.killed_enemies`，去重（同单位只记一次——用 id() 或先判 in）。
3. `to_state()` / 反序列化：killed_enemies 尽量随战斗状态序列化/恢复（防跨消息续战后胜利丢失记录；若 enemies 本身也是序列化的，照同样方式带；实现成本高则可放宽，报告说明）。
4. combat.py:821-826 胜利分支：把单次 `_handle_victory(..., _mon, ...)` 改为：先对 `b.killed_enemies`（含 _origin_enemy，按名字去重？**不，同名前缀的野猪/野猪·幼崽要各计一次**——逐个调 `_update_quests`）：
   ```python
   killed = list(getattr(b, "killed_enemies", None) or [])
   if not killed:
       killed = [_mon]
   if _mon and not any(k.get("name") == _mon.get("name") for k in killed):
       killed.insert(0, _mon)
   for k in killed:
       for _r in self._update_quests(group_id, qq_id, k):   # 注意 _update_quests 是同步还是异步？按现有 1920 行调用方式
           ...
   ```
   看 `_handle_victory` 内部怎么调 `_update_quests` 的（1920 是 `self._update_quests(...)` 直接调用）——**_handle_victory 内部不动**，在 _handle_victory 的调用方（821-826）展开：既然 _handle_victory 只收一个 monster，最简实现 = 在 for 循环里逐个调 _handle_victory？不行（会重复发经验/掉落）！**正确做法**：修改 `_handle_victory` 签名或内部——让 _update_quests 调用处（1918-1925 附近）遍历 killed_enemies。**以实际代码为准，原则：掉落/经验/金币只结算一次（用 _mon），任务进度（_update_quests）按 killed 逐个结算**。允许在 _handle_victory 内把单次 `_update_quests` 调用改为循环（把 battle 的 killed_enemies 传进去）。
5. 副本路径（instance.py:2179-2183 已有 killed 循环，不动）。
6. 注释标『v130.7 意见#17』。
